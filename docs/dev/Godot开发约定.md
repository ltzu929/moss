# Godot 开发约定

本页维护节点职责、场景通信和共享资源约束。当前接口见 [技术架构](技术架构.md)，
风格见 [代码规范](代码规范.md)，验证范围与判定见 [测试指南](测试指南.md)。

## 编辑器与 MCP

编辑器操作与运行验证使用 `godot-ai-mcp` Skill，复用根 AGENTS 规定的匹配会话。
纯文档任务不要求连接或启动 Godot。外部 Godot 文件修改后，在运行前刷新受影响的导入
与编辑器状态；处理磁盘重载提示，不把 `scene_open` 当前场景当作强制重载。

Godot AI v4 使用面板生成的 `godot-ai attach` stdio 配置；裸 HTTP URL 属于旧版方式。
迁移和认证问题按 [上游迁移说明](https://github.com/hi-godot/godot-ai/blob/main/docs/v4-migration.md)
或 Skill 的连接恢复分支处理。插件操作步骤不在工程文档重复维护。

`addons/` 是本地忽略的编辑器依赖。新检出要使用 MCP 时需要为该根目录配置插件；
独立测试的导入容错边界以现有运行器为准，不把插件重新加入 Git。

## 场景职责与通信

- 子场景通过语义信号报告操作，父层注入依赖并协调系统；不通过多层 `get_parent()` 操作外部状态。
- UI 不直接写核心游戏状态，领域系统不主动查找具体 UI 节点。MainOS 保留的编排职责以技术架构为准。
- 同一场景内的稳定节点可用 `%UniqueName`；跨组件只使用组件根公开接口，不依赖子组件内部路径。
- `setup()`、参数与 `@export` 分别用于运行时或编辑器依赖注入。必需依赖缺失导致功能不可用时，在边界报错或禁用相应交互。
- ActionLogView 只消费外部传入的完整条目；局势算法服务只消费显式状态和快照，不访问 MainOS 或 UI。具体对象分工见技术架构。

## Resource 与数据放置

`.tres` 是共享只读模板。运行时修改使用独立状态；需要资源副本时使用深复制，不能污染
其他主场景实例或同路径资源。SectorData、GameEvent、CommandData、TechNodeData 都遵守此边界。

| 数据 | 放置方式 |
|---|---|
| 事件、科技、区域初始值 | `.tres` |
| 策划可调参数 | `@export` 或 `.tres` |
| 固定算法阈值 | `const` |
| 运行态 | 成员变量或专门状态对象 |
| UI 颜色与间距 | Theme 或主题常量 |
| 稳定资源路径 | `preload` 或常量 |

## 已有故障对应的约束

- `_process()`／`_physics_process()` 不执行资源加载、目录扫描或文件访问；高频路径需要改进时依据可观察行为判断。
- `queue_free()` 到帧末才生效，不能在以 `get_child_count()` 为条件的循环中只调用它；同步缩容先移出场景树。
- 玩家可高频触发的动画、通知与待显示队列设置容量上限，避免领域历史有上限而显示队列无限积压。
- 自动换行 Label 自身配置正数横向 `custom_maximum_size`；运行时生成的 Label 在加入容器前按可用宽度设置，避免最小尺寸计算阶段缺少换行边界。

上述可机械检查的部分由 `tests/project_conventions_test.tscn` 执行。动态布局和队列行为
由相应专项测试验证；不要求普通修改重复检查所有条目。

## 场景与资源变更

场景结构优先通过编辑器／MCP 调整。外部修改 `.tscn` 后验证受影响场景可加载，关注
变化的资源引用、节点路径和信号连接。删除场景或脚本时同步处理对应 `.uid` 与有效引用。
强制事件的零能源方案属于 [数值设计](../design/数值设计.md) 的可玩性约束，不由运行时降级替代资源验收。

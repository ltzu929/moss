# Godot 开发约定

本文档维护 MOSS 项目的 Godot 工程约定：节点职责、场景通信、依赖注入、
Resource 生命周期、输入和生命周期边界。GDScript 书写风格见 `代码规范.md`，
当前运行时事实见 `技术架构.md`。

## 零、AI 与 MCP 会话门禁

本项目统一使用 `hi-godot/godot-ai`。仓库级 `.mcp.json` 指向
`http://127.0.0.1:8000/mcp`；旧的 `@coding-solo/godot-mcp` 不再是可用回退。

每次 AI 开发必须按以下顺序开始：

1. 列出 `godot-ai` 会话，按当前项目根目录的规范化绝对路径匹配。
2. 激活匹配会话并读取 `editor_state`，记录 Godot、插件和服务端版本。
3. 会话为 `ready` 时复用它；不得查找可执行文件、启动第二编辑器或对同一目录运行无头 Godot。
4. 工具未暴露时，先区分 MCP 端点、编辑器桥接和客户端工具注入三层状态。端口可达不证明当前 AI 已取得工具。

工具或会话异常时按以下顺序恢复，不得跳到旧 npm 服务或第二个编辑器：

1. 检查 `http://127.0.0.1:8000/mcp` 是否有 MCP 协议响应；连接拒绝或 502 时先检查本地服务、代理和 `127.0.0.1` 直连。
2. 端点可响应但当前客户端没有 `godot-ai` 工具时，判定为客户端工具注入问题，重连当前 MCP 客户端后再检查 `tools/list`。
3. 工具已出现后重新执行 `session_manage(list)`；按规范化项目绝对路径匹配，再 `session_activate` 和读取 `editor_state`。
4. 有匹配会话但不就绪时，检查现有 Godot 的插件启用状态、输出中的桥接就绪信息和编辑器错误；优先恢复或重载当前插件。
5. 只有会话列表、操作系统进程和项目路径都证明该项目编辑器已经关闭时，才允许启动编辑器；不得启用 `@coding-solo/godot-mcp` 作为回退。

诊断时分别记录“端点是否响应、工具是否注入、匹配会话是否 ready”三项结果，
不能用其中一项代替另外两项，也不能用 HTTP 返回的服务信息代替活动会话中的插件版本。

外部文件修改后的恢复顺序：停止运行中的游戏，重新扫描或导入修改文件，处理
“从磁盘重新加载”提示，再用 `scene_get_hierarchy`、`script_manage(find_symbols)`
确认编辑器内存与磁盘一致。`scene_open` 打开当前场景是空操作，不能当作强制重载。

运行验证必须使用新的 `run_id`。短测试需要同时满足：目标场景确实启动、运行已经
停止、出现该测试的最终标记或断言数、没有 `[FAIL]`/脚本解析错误/错误级日志。
编辑器打开时通过 MCP 运行测试场景；只有关闭编辑器后，才运行独立入口
`python tools/run_godot_tests.py`。

## 一、节点与对象职责

选择基类时先看职责，而不是只看画面效果。

| 类型 | 使用场景 |
|------|----------|
| `Control` | 屏幕 UI、容器布局、GUI 输入、HUD 和弹窗 |
| `Node2D` | 二维世界坐标中的对象、碰撞或地图实体 |
| `Resource` | 纯数据、配置、可复用编辑器资源 |
| `RefCounted` | 不需要场景树生命周期的纯逻辑对象 |
| `Node` | 需要生命周期、信号、子节点或场景树关系的系统 |

## 二、场景通信

场景默认应能独立理解和运行。需要外部上下文时，由上层注入依赖并负责协调。

### 2.1 强制规则

- 子场景不得通过多层 `get_parent()` 操作外部状态。
- 子场景通过信号报告用户操作或状态变化。
- 父节点负责连接信号、查找领域对象并协调多个系统。
- 外部依赖通过 `setup()`、参数、导出属性或父节点注入。
- UI 不直接修改核心游戏状态。
- 核心系统不主动查找具体 UI 节点，除非当前架构文档明确它仍由主控制器负责。

### 2.2 推荐模式

当前地图选择流程是本项目的推荐模式：

```text
WorldMapView 发出 region_selected(region_id)
        ↓
main_os.gd 查找对应 SectorInfo
        ↓
main_os.gd 统一更新选择状态和地图显示
```

子场景只表达“发生了什么”，不决定“外部系统应该怎么变”。

行动日志显示流程也遵循这一边界：

```text
MainOS.record_action() 构造领域条目
        ↓
ActionLogView.append_entry(entry) 管理显示队列与真实节点
        ↓
MainOS 重开时调用 ActionLogView.clear()
```

`ActionLogView` 不读取 `MainOS`、年月或资源；测试通过组件公开接口和真实子节点结果检查
容量、打字机状态与重开取消，不访问组件私有字段。

## 三、节点访问与依赖注入

- 同一场景内部的稳定节点可使用 `%UniqueName`。
- 跨场景访问优先由父节点持有引用并调用公开方法。
- 不把具体节点路径散落到多个脚本中。
- `setup()` 用于运行时注入必需依赖；如果依赖缺失会导致功能不可用，应尽早
  `push_error()` 或禁用交互。
- `@export` 用于编辑器可配置依赖，适合静态场景布局和资源引用。

## 四、Resource 共享

`.tres` 默认视为只读模板。运行时需要修改数据时，应创建独立状态对象，或在
明确需要复制资源时使用 `duplicate(true)`。

Godot 会复用已加载路径对应的 Resource。直接修改共享 Resource 可能影响所有
引用同一路径资源的节点。

### 4.1 存放边界

| 数据类型 | 存放方式 |
|----------|----------|
| 事件、科技、区域初始值 | `.tres` |
| 策划需要调节的参数 | `@export` 或 `.tres` |
| 固定算法阈值 | `const` |
| 运行时状态 | 成员变量或专门状态对象 |
| UI 颜色和间距 | Theme 或主题常量 |
| 稳定资源路径 | `preload` 或常量 |

### 4.2 项目注意事项

`SectorData`、`GameEvent`、`CommandData` 和 `TechNodeData` 都是配置资源。
如果某个系统要长期改变区域或科技状态，必须确认修改的是运行时状态，而不是
共享模板。

## 五、生命周期、输入与性能

### 5.1 生命周期函数

- `_ready()`：读取节点引用、连接信号、初始化本场景状态。
- `_process()`：只用于确实需要每帧更新的视觉或逻辑。
- `_physics_process()`：物理移动、碰撞和固定步长逻辑。
- `_gui_input()`：`Control` 自身的鼠标键盘交互。
- `_unhandled_input()`：全局游戏输入或覆盖层快捷键。

不需要每帧执行的逻辑优先使用信号、事件触发或 `Timer`。

### 5.2 性能约定

- 不在 `_process()` 中重复 `load()`、查找节点或读取磁盘。
- 不为了“可能更快”提前复杂化实现；先用 Profiler 或可观察卡顿证明问题。
- 高频回调中的字符串拼接、资源扫描和场景树遍历应有明确理由。
- `queue_free()` 只会在当前帧结束时真正删除节点；调用后父节点的
  `get_child_count()` 不会立刻减少。不得用该计数作为 `while` 条件并在循环体中
  只调用 `queue_free()`。需要同步缩容时，先 `remove_child()`，再 `queue_free()`，
  并使用预先计算的有限次数循环。
- 所有可能由玩家高频触发的显示队列都必须设置容量上限；不能只限制领域历史，
  却让动画、通知或待显示队列无限积压。

## 六、场景文件与验证

- 场景结构优先通过 Godot 编辑器或 Godot MCP 修改。
- 手动编辑 `.tscn` 时必须保持资源引用、节点路径和唯一节点名称有效。
- 启用 `autowrap_mode` 的 `Label` 必须在自身配置正数横向
  `custom_maximum_size`；运行时代码创建的自动换行 `Label` 也必须在加入容器前，
  按容器可用宽度设置最大宽度。不得只依赖容器最终分配的 `size.x`，因为 Label
  在最小尺寸计算阶段仍然缺少换行边界。
- 修改场景、节点路径、信号连接或导出资源后，至少运行相关场景加载或测试。
- 删除场景或脚本时同步清理 `.uid`、文档和测试引用。
- 低误伤的工程约定由 `tests/project_conventions_test.tscn` 自动检查。
- 强制事件必须至少包含一个零能源方案；运行时紧急降级只是防止坏数据造成软锁，不能替代资源验收。

## 七、和架构文档的边界

本文档描述“以后应该怎么写”。`技术架构.md` 描述“当前已经是什么样”。

例如 `main_os.gd` 目前仍是主控制器，这是架构事实；是否拆分它属于专项架构
评估，不由本文档直接宣布完成或强制执行。

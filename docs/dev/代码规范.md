# GDScript 代码规范 - MOSS 模拟器项目

本文档只维护 GDScript 书写风格、类型标注、注释规范和局部实现注意事项。
节点职责、场景通信、Resource 生命周期和输入/生命周期边界见
`Godot开发约定.md`；运行时事实见 `技术架构.md`；测试入口见
`测试指南.md`。

> 参考官方 GDScript 风格指南，适配本项目需求。

---

## 一、规则强度

| 等级 | 含义 | 示例 |
|------|------|------|
| 必须 | 违反后不得提交，通常可由静态检查或明确 review 判断 | 函数签名类型、信号参数类型、`.emit()` 发射 |
| 应该 | 默认遵守，允许有明确理由例外 | 静态类型优先、公共接口文档注释、100 字符行宽 |
| 建议 | 提高可读性的经验规则，不作为硬性门禁 | 大型区域分隔注释、小文件的组织细节 |

除非单独标注，本文规则默认为“应该”。

---

## 二、命名规范

### 2.1 基本规则

| 类型 | 命名风格 | 示例 | 强度 |
|------|----------|------|------|
| 类名 | PascalCase | `SectorData`, `GameEvent`, `EventOption` | 必须 |
| 函数名 | snake_case | `load_events_from_disk()`, `get_average_authority()` | 必须 |
| 变量名 | snake_case | `current_year`, `avg_authority`, `total_count` | 必须 |
| 常量 | CONST_CASE | `MAX_YEAR = 2075` | 必须 |
| 信号 | snake_case | `game_ended`, `option_selected` | 必须 |
| 枚举 | PascalCase | `enum GameState { Running, Paused, Ended }` | 应该 |
| 枚举值 | CONST_CASE | `GameState.RUNNING` | 应该 |

### 2.2 节点命名

- 节点名称使用 PascalCase：`SectorInfoAsia`, `EventPopup`。
- 唯一节点使用 `%` 唯一名称访问：`%YearLabel`, `%EventPopup`。

### 2.3 文件命名

- 脚本文件：snake_case.gd，例如 `main_os.gd`, `sector_info.gd`。
- 场景文件：snake_case.tscn，例如 `event_popup.tscn`。
- 资源文件：snake_case.tres，例如 `sector_asia.tres`, `event_2044_space_elevator_crisis.tres`。

## 三、代码组织

### 3.1 文件结构顺序

`.gd` 文件按以下顺序组织：

```text
01. class_name 定义（如果需要）
02. extends 继承声明
03. 信号定义
04. 导出变量（@export）
05. 常量/枚举
06. 成员变量
07. 生命周期函数（_ready, _process, _input 等）
08. 公共函数（供外部调用）
09. 私有函数/回调函数（内部使用，以 _ 开头）
```

小文件可以省略显式区域标题，但顺序仍应保持稳定。

### 3.2 区域分隔

超过约 100 行，或包含三个以上职责区域的脚本，建议使用区域分隔注释。
小型脚本不强制添加大型分隔注释，避免噪音。

```gdscript
# ============
# 信号定义
# ============

signal game_ended(result: String)
```

## 四、注释规范

### 4.1 文档注释

`##` 文档注释用于公共接口、信号、导出属性、非直观算法和有明显副作用的方法。
简单 getter、局部回调和一眼可读的私有函数不强制逐个解释。

```gdscript
## 从硬盘目录加载所有事件资源文件。
## 自动扫描 res://data/events/ 下的 .tres 文件。
func load_events_from_disk() -> void:
```

### 4.2 行内注释

使用 `#` 解释复杂逻辑、约束来源或临时防护，不重复描述代码字面含义。

```gdscript
# 类型安全检查：防止加载非事件资源。
if event is GameEvent:
	all_events.append(event)
```

### 4.3 注释语言

- 注释、调试信息、UI 文本、事件数据和项目文档使用中文。
- 代码标识符使用英文。

## 五、类型标注

### 5.1 函数签名

所有函数必须标注参数和返回值类型。

```gdscript
func apply_consequences(
	event_name: String,
	order_delta: int,
	hope_delta: int
) -> void:
	...
```

### 5.2 静态类型优先

项目默认采用静态类型优先。右侧类型明确时使用 `:=`；成员变量、参数、返回值、
节点查找、字典读取和 Variant 返回值使用显式类型。

```gdscript
# 右侧类型明确。
var path := "res://data/events/"
var map_rect := _get_map_rect()

# Dictionary、节点查找或 Variant 返回值。
var texture: Texture2D = _region_textures.get(region_name)
var selected_sector: SectorInfo = null
```

不使用无类型声明。

```gdscript
var path = "res://data/events/"  # 不推荐：类型不明确。
```

### 5.3 项目警告

建议逐步收敛以下 Godot 警告，但不把现有代码一次性迁移作为普通文档修改的前置条件：

- `UNTYPED_DECLARATION`
- `UNSAFE_METHOD_ACCESS`
- `UNSAFE_PROPERTY_ACCESS`

## 六、信号规范

### 6.1 信号定义

信号参数必须标注类型。

```gdscript
signal game_ended(result: String, message: String)
signal option_selected(index: int)
```

### 6.2 信号发射

必须使用 `.emit()` 显式发射。

```gdscript
game_ended.emit("failed", "控制权丧失")
option_selected.emit(0)
```

### 6.3 信号连接

优先使用 `.connect()` 直接连接。

```gdscript
restart_btn.pressed.connect(_on_restart_pressed)
```

场景之间的通信边界见 `Godot开发约定.md`。

## 七、错误处理

### 7.1 错误报告

使用 `push_error()` 和 `push_warning()` 表达可见问题。`print()` 只用于临时调试
或测试输出。

```gdscript
push_error("找不到板块: " + event_name)
push_warning("事件目录不存在: " + path)
print("加载事件: " + file_name)
```

### 7.2 类型检查

加载资源或处理外部输入时使用 `is` 做类型安全检查。

```gdscript
if event is GameEvent:
	all_events.append(event)
```

## 八、代码风格

### 8.1 缩进与空格

- 使用 Tab 缩进（Godot 默认）。
- 函数参数换行时逐行排列。

```gdscript
func apply_consequences(
	event_name: String,
	order_delta: int,
	hope_delta: int,
	energy_cost: int
) -> void:
```

### 8.2 空行规范

- 函数之间保留一个空行。
- 区域分隔注释前后保留一个空行。
- 逻辑块之间可适当添加空行提高可读性。

### 8.3 行长度

单行代码应该不超过 100 字符。过长代码适当换行；无法自然换行的资源路径、
文案或 Godot 场景属性可作为例外。

## 九、项目局部约定

### 9.1 数据驱动边界

可配置游戏数据优先放入 `.tres` 或 `@export`，但不是所有数值都应搬进资源。

| 数据类型 | 存放方式 |
|----------|----------|
| 事件、科技、区域初始值 | `.tres` |
| 玩家或策划需要调整的参数 | `@export` 或 `.tres` |
| 固定算法阈值 | `const` |
| 运行时状态 | 成员变量 |
| UI 颜色和间距 | Theme 或主题常量 |
| 稳定资源路径 | `preload` 或常量 |

### 9.2 场景文件注意事项

- 场景结构优先通过 Godot 编辑器或 Godot MCP 创建和配置。
- 必要时可以谨慎编辑 `.tscn`，但必须保持资源引用、节点路径和唯一节点名称有效。
- 手动修改场景后必须重新加载场景并运行相关测试。
- 适合运行时生成的 UI 可以使用代码创建。

## 十、GDScript 4.x 注意事项

### 10.1 常量类型限制

`const` 只支持基础类型和未类型化数组/字典。复杂类型用 `var` 加类型标注。

```gdscript
# 不允许。
const INITIAL_AUTHORITIES: Dictionary = {"亚洲": 24, "北美": 26}

# 推荐。
var _initial_authorities: Dictionary = {"亚洲": 24, "北美": 26}
```

### 10.2 节点路径检查

`has_node()` 不使用 `^` 唯一名前缀。

```gdscript
has_node("Timer")
has_node("%UniqueName")
```

### 10.3 Resource 类型检查

加载 `.tres` 资源后使用 `is` 做类型检查。

```gdscript
if event is GameEvent:
	all_events.append(event)
```

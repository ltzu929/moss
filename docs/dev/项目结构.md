## 关键职责

### 数据

- `scripts/resources/game_event.gd` 与 `event_option.gd`：事件和选项数据结构。
- `scripts/resources/sector_data.gd`：区域状态数据。
- `scripts/resources/region_identity.gd`：区域稳定 ID 与显示名称的单向边界映射。
- `GameEvent.event_id`、`EventOption.option_id` 与 `SectorData.region_id`：跨资源稳定身份；标题、按钮文字和区域名称仍属于显示内容。
- `scripts/resources/command_data.gd`：指令消耗、效果与冷却。
- `scripts/resources/tech_node_data.gd`：科技节点、路线、阶段和标签数据。
- `scripts/resources/situation_data.gd` 与 `situation_approach_data.gd`：随机局势模板、生成条件、风险权重和持续方针数据。
- `scripts/resources/situation_node_data.gd` 与 `situation_node_option_data.gd`：每项局势至多一个的阶段节点及两个确定性方案。
- `data/`：上述类型的实际资源配置。

### 运行时

- `scripts/systems/main_os.gd`：拥有内容加载结果数组、推进年月、处理事件流程、协调指令、保存行动日志领域条目、通过两个 UI 根组件的公开接口同步显示、判定结局与重新开始。
- `scripts/systems/game_content_loader.gd`：不依赖场景树，按文件名扫描事件/局势/指令 `.tres`；事件和局势返回模板，指令返回每个主场景独立的 `duplicate(true)` 运行态副本。
- `scripts/systems/event_state_store.gd`：保存、查询、导出和清空中型事件/条件分支的轻量状态；不访问主场景、资源模板或 UI。
- `scripts/systems/event_narrative_system.gd`：读取轻量状态与核心决策历史，生成主事件历史回声和选项显示后缀；不修改事件数值字段。
- `scripts/systems/event_resolution_system.gd`：读取运行时事件副本、历史快照、科技能力和板块/能源快照，生成事件选项的预览与结算投影；不写场景、资源、能源、UI 或日志。
- `scripts/systems/ending_system.gd`：读取平均社会状态、科技能力、核心决策和轻量事件状态快照，生成四类结局判定、历史回顾和科技摘要；不访问主场景、节点或 UI。
- `RegionIdentity`、`event_id`、`option_id` 与 `region_id`：运行时跨系统只传稳定 ID；显示层按需恢复标题、按钮文字和区域名称。
- `scripts/systems/command_system.gd`：指令查找、科技解锁、参数覆盖、可用性、冷却、执行结算和指令数值效果。
- `scripts/systems/decision_history.gd`：不可逆核心标签、可读档案记录和只写一次约束。
- `scripts/systems/development_log.gd`：开发期 JSONL 检查点、关键阶段同步路径记录和双槽低频心跳，分别写入 `user://moss_development_diagnostics.jsonl` 与 `user://moss_runtime_heartbeat_a.json`、`user://moss_runtime_heartbeat_b.json`，用于崩溃或主线程卡死后定位最后运行状态。
- `scripts/systems/situation_instance_state.gd`：保存单项局势的类型化可变运行态，并导出不含 Resource 引用的可恢复基础类型快照。
- `scripts/systems/situation_spawn_planner.gd`：按显式年月、事实、活跃地区和冷却计算模板/地区资格、风险权重与候选排序；不持有集合或 RNG。
- `scripts/systems/situation_funding_planner.gd`：按真实逆序结算顺序计算每项局势的 CPU/能源计划；只读输入，不修改资源或运行态。
- `scripts/systems/situation_month_resolver.gd`：在状态副本上计算持续成本、严重度/阶段、断供惩罚和节点激活，返回变更结果；不删除集合、不访问 UI。
- `scripts/systems/situation_snapshot_builder.gd`：只读构建 active/node/方针快照、通知和历史回声，保持既有 Dictionary 字段和值语义。
- `scripts/systems/situation_system.gd`：拥有局势集合、RNG、冷却和历史，负责调用算法服务并编排资源扣除、完成移除、结算和运行态事务；保留 UI/主循环 Dictionary 协议并校验运行态快照。
- `scripts/systems/technology_system.gd`：协议点、节点激活、阶段和科技标签。
- `scripts/ui/technology_screen.gd`：索引静态科技场景、同步系统状态及处理不可逆确认交互。
- `scripts/ui/technology_node_card.gd`：科技资源预览、节点状态样式和点击信号。
- `scripts/ui/main_hud.gd`：拥有顶栏资源、日期进度、档案/科技/局势/时间入口和指令坞；只接收快照并发出语义信号。
- `scripts/ui/strategic_workspace.gd`：拥有世界地图、区域详情、全局概览、局势摘要、行动日志和六张区域卡；提供稳定区域 ID 的选择与刷新接口，不推进时间或结算资源。
- `scripts/ui/world_map_view.gd`：可点击世界地图和区域状态绘制。
- `scripts/ui/region_orbital_view.gd`：右侧 3D 地球聚焦视图。
- `scripts/ui/event_popup.gd`：事件报告、选项和延迟影响提示。
- `scripts/ui/decision_archive_panel.gd`：核心决策记录的可复用展示组件。
- `scripts/ui/situation_panel.gd`：最多两项局势的非模态追踪、历史回声、详情、方针和内联节点交互。
- `scripts/ui/action_log_view.gd`：行动日志标签、打字机队列、容量淘汰、滚动、光标和重开取消；只接收父节点传入的完整领域条目。
- `scripts/ui/moss_ui_theme.gd`：当前 HUD 的共享样式。

### 测试

- `tests/test_runner.tscn`、`tests/test_runner_managed.tscn`、`tests/test_runner_human_autonomy.tscn`：混合、托管和人类自主三条完整路线入口。

- `tests/support/moss_test_case.gd`：为独立测试统一提供失败计数、真值断言和相等
  断言；新增测试不再复制同类辅助代码。
- `tests/support/playthrough_route_catalog.gd`：集中维护三条路线的科技、指令和事件选择配置。
- `tests/support/playthrough_driver.gd`：驱动月度推进、真实事件按钮、指令、局势方针和弹窗响应。

- `tools/godot_test_catalog.py`：维护冻结的 35 项 `TEST_SPECS` 顺序、四层
  `suite`、`headless/display` 模式、终止标记和 CLI 选择规则。

  内存采样和 124/125 退出码门禁。
- `tools/godot_test_evaluator.py`：负责严格错误白名单、终止标记、失败原因和逐场景
  `SceneResult` 判定。
- `tools/godot_test_reporter.py`：负责保持 `ensure_ascii=False` 的 JSON 报告以及
  GitHub Job Summary 的双导入、逐场景和峰值内存表格。
- `tools/run_godot_tests.py`：只负责 CLI 参数解析和按双导入→逐场景顺序串行编排；
  继续保留原直接调用方式与历史模块导出。
- `tools/audit_content_identity.py`：按资源路径建立事件、选项和区域身份映射，收集选项

## 放置约定

- 可配置游戏数据放在 `data/`，使用带类型的 `.tres` Resource。
- 通用数据结构放在 `scripts/resources/`。
- 当前跨系统流程放在 `scripts/systems/`；是否继续拆分由专项架构评估决定。
- UI 行为和视觉组件放在 `scripts/ui/`；UI 按钮只展示业务系统传入的可用性结果。
- 场景放在 `scenes/`，素材放在 `assets/`。
- 科技树的 `.tres` 保存节点数据，场景实例保存固定资源引用和布局；增删节点必须同步修改两者。
- 自动化入口和测试辅助代码放在 `tests/`。
- 产品与规则文档放在 `docs/design/`，工程文档放在 `docs/dev/`，史料和来源规则放在 `docs/lore/`，结构化世界观资料放在 `docs/worldbuilding/`。
- 不保留阶段性设计包或重复索引；其中仍有持续价值的结论应合并进 `docs/design/`、`docs/dev/`、`docs/lore/` 或 `docs/worldbuilding/` 的权威入口。

## 场景编辑

优先通过 Godot 编辑器或 Godot MCP 修改节点结构和属性。手动编辑 `.tscn` 时必须保持资源引用、节点路径和唯一节点名称有效，并在修改后运行场景加载或自动化测试。

## 关键职责

### 数据

- `scripts/resources/game_event.gd` 与 `event_option.gd`：事件和选项数据结构。
- `scripts/resources/sector_data.gd`：区域状态数据。
- `scripts/resources/command_data.gd`：指令消耗、效果与冷却。
- `scripts/resources/tech_node_data.gd`：科技节点、路线、阶段和标签数据。
- `scripts/resources/situation_data.gd` 与 `situation_approach_data.gd`：随机局势模板、生成条件、风险权重和持续方针数据。
- `scripts/resources/situation_node_data.gd` 与 `situation_node_option_data.gd`：每项局势至多一个的阶段节点及两个确定性方案。
- `data/`：上述类型的实际资源配置。

### 运行时

- `scripts/systems/main_os.gd`：加载资源、推进年月、处理事件流程、协调指令、同步 UI、判定结局与重新开始。
- `scripts/systems/command_system.gd`：指令查找、科技解锁、参数覆盖、可用性、冷却、执行结算和指令数值效果。
- `scripts/systems/decision_history.gd`：不可逆核心标签、可读档案记录和只写一次约束。
- `scripts/systems/development_log.gd`：开发期 JSONL 检查点、关键阶段同步路径记录和原子替换的低频心跳，分别写入 `user://moss_development_diagnostics.jsonl` 与 `user://moss_runtime_heartbeat.json`，用于崩溃或主线程卡死后定位最后运行状态。
- `scripts/systems/situation_system.gd`：局势随机生成、事实过滤、月度推进、严重度阶段、方针、单次节点、轻量历史、冷却和结算。
- `scripts/systems/technology_system.gd`：协议点、节点激活、阶段和科技标签。
- `scripts/ui/technology_screen.gd`：索引静态科技场景、同步系统状态及处理不可逆确认交互。
- `scripts/ui/technology_node_card.gd`：科技资源预览、节点状态样式和点击信号。
- `scripts/ui/world_map_view.gd`：可点击世界地图和区域状态绘制。
- `scripts/ui/region_orbital_view.gd`：右侧 3D 地球聚焦视图。
- `scripts/ui/event_popup.gd`：事件报告、选项和延迟影响提示。
- `scripts/ui/decision_archive_panel.gd`：核心决策记录的可复用展示组件。
- `scripts/ui/situation_panel.gd`：最多两项局势的非模态追踪、历史回声、详情、方针和内联节点交互。
- `scripts/ui/moss_ui_theme.gd`：当前 HUD 的共享样式。

### 测试

- `tests/test_runner.tscn`、`tests/test_runner_managed.tscn`、`tests/test_runner_human_autonomy.tscn`：混合、托管和人类自主三条完整路线入口。
- `tests/test_runner.gd`：共享实例化主场景、加速时间、执行真实指令与局势方针、自动响应弹窗并按路线执行断言。
- `tests/support/moss_test_case.gd`：为独立测试统一提供失败计数、真值断言和相等
  断言；新增测试不再复制同类辅助代码。
- `tools/run_godot_tests.py`：统一注册 `contracts`、`domain`、`ui` 和
  `playthrough` 四层，执行双导入、逐场景超时、最终标记与错误日志门禁，并可输出
  JSON 报告。
- `tools/tests/test_run_godot_tests.py`：检查测试筛选、错误白名单、超时和报告协议，
  不启动 Godot。
- `tests/command_system_test.tscn`：检查指令领域规则、效果结算和按钮展示边界。
- `tests/base_resource_contract_test.tscn`：检查六个区域资源、两条基础指令、数值
  设计和主场景运行态装配契约。
- `tests/development_log_test.tscn`：检查开发诊断 JSONL、关键阶段同步落盘、运行中轮转、原子心跳替换失败保护和主场景启动快照。
- `tests/time_system_test.tscn`：检查月份推进、年度结算、非一月事件和重开日期。
- `tests/event_state_test.tscn`：检查事件选项写入轻量事件状态，以及重开清理。
- `tests/event_playability_test.tscn`：检查 25 个事件的零能源保底、触发键、条件门槛和运行时防软锁。
- `tests/decision_history_test.tscn`：检查五个核心决策写入、三组组合或后续回读、档案展示、结局解释和重开清理。
- `tests/branch_event_test.tscn`：检查两个条件短分支的资源、真实触发、六种状态回读和重开清理。
- `tests/resource_isolation_test.tscn`：检查区域与指令运行态不会污染其他实例或 `.tres` 模板。
- `tests/mid_event_resource_test.tscn`：检查 17 个中型事件资源的年月、选项和状态值。
- `tests/project_hygiene_test.tscn`：检查废弃路径不会回归，并加载所有保留场景。
- `tests/project_conventions_test.tscn`：检查低误伤的代码规范和 Godot 工程约定。
- `tests/technology_system_test.tscn`：检查 21 节点科技图、协议点、阶段、前置、
  标签、重置和快照。
- `tests/technology_gameplay_test.tscn`：检查科技解锁、指令效果、资源上限、恢复率
  和重开。
- `tests/technology_ending_test.tscn`：检查四类结局、控制权归零规则和结局历史回顾。
- `tests/technology_ui_test.tscn`：检查科技节点布局、状态、详情、激活和模态交互。
- `tests/world_map_view_test.tscn`：检查世界地图遮罩、点击和主场景选区同步。
- `tests/situation_system_test.tscn`：检查九类资源、并发、事实门槛、方针、节点、历史、断供、指令干预和固定种子。
- `tests/situation_ui_test.tscn`：检查顶部入口、非模态详情、内联节点、方针回写、时间控制与双分辨率边界。
- `tests/ui_layout_1080p_test.tscn`：检查 display 模式下 1920×1080 真实视口、
  世界地图观察面积和主布局边界。

## 放置约定

- 可配置游戏数据放在 `data/`，使用带类型的 `.tres` Resource。
- 通用数据结构放在 `scripts/resources/`。
- 当前跨系统流程放在 `scripts/systems/`；是否继续拆分由专项架构评估决定。
- UI 行为和视觉组件放在 `scripts/ui/`；UI 按钮只展示业务系统传入的可用性结果。
- 场景放在 `scenes/`，素材放在 `assets/`。
- 科技树的 `.tres` 保存节点数据，场景实例保存固定资源引用和布局；增删节点必须同步修改两者。
- 自动化入口和测试辅助代码放在 `tests/`。
- 产品与规则文档放在 `docs/design/`，工程文档放在 `docs/dev/`，史料和来源规则放在 `docs/lore/`，结构化世界观资料放在 `docs/worldbuilding/`。
- 不保留阶段性设计包或重复索引；其中仍有持续价值的结论应合并进 `docs/design/`、`docs/dev/`、`docs/lore/` 或 `docs/worldbuilding/` 的权威入口。

## 场景编辑

优先通过 Godot 编辑器或 Godot MCP 修改节点结构和属性。手动编辑 `.tscn` 时必须保持资源引用、节点路径和唯一节点名称有效，并在修改后运行场景加载或自动化测试。

## 三、执行方式与硬性规则

### 3.1 每个执行单元循环

1. 从已拉取最新的 `main` 开始，先保护无关工作区改动；PR 7–13 是计划单元编号，不要求默认创建功能分支。
2. 开工前做代码事实核对：搜索真实函数、行号、调用点，与计划不符时以代码为准并在交付说明中登记偏差。
3. 在 `main` 实现最小一致切片，只移动职责，不混入玩法、数值或文案调整。
4. 跑对应专项测试、当前注册表全部场景和三条完整路线，记录本次 `run_id`、最终标记和错误日志。
5. 同一执行单元内同步受影响权威文档，完整审查 diff 后提交到 `main`。
6. 提交后由其他 AI 或人工复核；阻塞项直接在 `main` 追加聚焦修复提交并重跑受影响门禁，不改写已审查历史。
7. 用户要求远端审查、禁止直接提交或要求合并前审查时，才使用分支和 Draft PR；其他情况推送 `main` 并核对云端状态。

### 3.2 Godot MCP 门禁与测试证据

- 外部修改 `.gd` / `.tres` / `.tscn` 后必须通过当前 `godot-ai` 会话重新扫描或导入。
- 编辑器打开时通过 MCP 会话运行测试；编辑器关闭时才可运行 `python tools/run_godot_tests.py`。
- 测试证据必须包含本次 `run_id`、最终标记、错误日志；不得用旧日志或"场景能打开"代替。

### 3.3 每个执行单元的统一验收

1. 当前注册表中的全部测试通过（不以固定数量为验收条件）。
2. 三条完整通关路线通过且结局不变（混合→共存；托管→MOSS 托管；人类自主→人类自主）。
3. 对应专项夹具比对通过。
4. 私有访问审计没有新增类型、没有增加次数。
5. 本执行单元指定的私有访问基线条目已经删除。
6. `.gd` / `.tres` / `.tscn` 修改后已通过 Godot MCP 重新导入。
7. 记录本次 `run_id`、最终标记和错误日志。
8. 对应权威文档在同一执行单元更新。
9. 交付说明列出：职责移动清单、明确未改变的行为、文档同步清单、测试证据、已知后续事项。
10. 不允许把当前执行单元的失败留给下一个结构单元修复。

### 第一批完成后 → 事件领域（PR 3–6，细化版）

本节基于 2026-08-07 的当前代码事实细化，不改变已经批准的事件内容、数值和时间线。当前事件资源为 25 个：6 个主事件、17 个中型事件、2 个条件短分支；共有 19 个 `event_state.*` 状态键、5 个核心决策键和 75 个选项。`main_os.gd` 目前 3116 行、143 个函数，事件领域的主要集中区为事件弹窗协调、1336–1824 行的事件读写/叙事/调整，以及 2356–2690 行的结局判定/正文。

#### 5.1 领域边界与依赖方向

事件领域只拆纯规则和文本构建；`MainOS` 仍是场景编排器。四个服务的职责和禁止依赖如下：

| 服务 | 迁移职责 | 显式输入/输出 | 明确不做 |
|---|---|---|---|
| `EventStateStore` | 保存、查询、导出和清空 `event_states` | `String` 状态键/值；返回只读语义的副本或标量 | 不访问 `MainOS`、节点、Resource 模板、UI 或日志；不接管 `DecisionHistory` |
| `EventNarrativeSystem` | 历史回声、事件描述拼接、选项显示文案 | `GameEvent`、`EventStateStore`、`DecisionHistory` 的显式读取；返回文本或独立运行时事件副本 | 不修改 `order_delta`、`hope_delta`、`authority_delta`、`energy_cost`；不读取当前能源或板块节点 |
| `EventResolutionSystem` | 科技减免、历史数值调整、能源消耗和限幅 | 事件/选项副本、前序事实、科技能力快照和当前资源；返回纯数值结算结果 | 不写板块、不改能源、不写日志、不访问弹窗；preview 与 resolve 共用同一底层计算路径，但允许通过兼容投影分别暴露原始预览值和最终结算值 |
| `EndingSystem` | 失败/结局判定、标题正文、历史回顾、科技摘要 | 平均状态、科技能力/核心名称、决策历史和事件状态的显式快照；返回结局结果与文本 | 不停止 Timer、不发信号、不创建结局场景、不写行动日志 |

依赖方向固定为“事实存储/只读服务 → 事件领域服务 → `MainOS` 适配器”。不新增巨型
`GameState`、全局 EventBus、Autoload 业务系统或依赖注入框架。`DecisionHistory` 继续作为
独立的不可逆历史服务，`EventStateStore` 只负责轻量 `event_state.*`，两者不能合并。

以下职责在本批次留在 `MainOS`：`process_month_tick()`、Timer 信号转发、

## 七、风险与控制

| 风险 | 控制 |
|---|---|
| Timer 与 await（`await %EventPopup.option_selected`） | 事件弹窗协调留在 MainOS，前几个 PR 不移动 |
| Resource 共享 | 区域、基础指令、事件选项继续复制运行时副本；任何重构不得直接修改磁盘加载的 `.tres` 模板 |
| 子场景唯一节点 | MainOS 不跨场景访问子组件内部 `%Node`，只经组件根节点公开方法与信号 |
| 随机局势顺序 | 局势逆序处理活跃实例；预测与真实扣费共用同一 FundingPlanner |
| 测试访问私有实现 | 先提供稳定公共接口再改测试；机器审计门禁（PR 1a 起 `--fail-on-new`，PR 13 后 `--require-zero`） |
| 诊断日志协议 | 诊断事件名、阶段名、JSON 字段、心跳格式拆分时不得重命名 |
| 计划与代码事实漂移 | 每个 PR 开工前代码事实核对；发现计划错误时以代码为准并在 PR 描述注明偏差 |

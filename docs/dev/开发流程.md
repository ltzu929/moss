# 开发流程

本文档维护当前开发顺序和完成标准。产品规则见 `../design/游戏设计.md`，代码事实见 `技术架构.md`。

## 当前主要缺口

| 缺口 | 当前问题 |
|------|----------|
| 事件因果 | 中型事件已写入轻量状态，地下城民生链已开始影响 2053 和 2075 主事件文案，其余链路仍待接入 |
| 决策历史 | 只有当前数值和动作日志，没有稳定历史标签 |
| 分支内容 | 尚无由历史选择触发的短分支事件 |
| 结局解释 | 科技终端已进入摘要，地下城民生状态已进入 2075 事件回声，但结局界面尚未系统读取关键事件历史 |
| 时间控制 | 月 tick 自动推进可运行，暂停与调速尚未形成正式规则 |
| 路线测试 | 科技路线已有专项覆盖，事件历史路线仍需补充 |

## 后续工作顺序

1. 设计六个主事件之间的因果关系。
2. 定义约 3 至 5 个不可逆决策标签。
3. 继续选择少量代表事件读取决策标签、轻量事件状态和科技标签。
4. 将历史标签与关键轻量事件状态加入结局解释和代表路线测试。
5. 在接口稳定后再评估是否拆分 `main_os.gd`。

本轮新增科技暂不接入事件系统；这是一条明确边界，不是遗漏。

## 实现验收原则

- 新系统必须服务长期选择，而不是只增加按钮或数值。
- 已实现状态必须有代码、场景和专项测试证据。
- UI 调整必须同时验证 1920×1080 和较小视口的响应式边界。
- `@tool` 预览必须在编辑器中可见，运行时接口不得因此改变。
- 外部文件编辑后必须重新导入，并通过当前 Godot 会话运行测试。
- 不启动第二个 Godot，不在编辑器已打开时运行独立无头测试。

## 近期明确不做

- 回合制时间重构。
- 新增第五类结局。
- 将本轮九个新增科技接入事件内容。
- 未经专项评估的 `main_os.gd` 拆分。

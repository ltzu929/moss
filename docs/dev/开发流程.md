# 开发流程

本文档维护当前开发顺序和完成标准。产品规则见 `../design/游戏设计.md`，代码事实见 `技术架构.md`。

## 当前主要缺口

| 缺口 | 当前问题 |
|------|----------|
| 事件因果 | 17 个中型事件轻量状态已进入主事件“历史回声”文案，2058、2065、2070 已有代表状态接入主事件选项代价，首批 4 个条件分支事件已接入 |
| 决策历史 | 5 个主事件核心历史标签已写入运行时因果档案，后续仍需评估存档持久化 |
| 分支内容 | 已有首批由核心标签或轻量状态触发的短分支事件，后续需要扩展路线组合和文本平衡 |
| 结局解释 | 科技终端已进入摘要，核心历史进入“核心历史”，代表轻量事件状态进入“历史回顾”，后续仍需补更多路线组合 |
| 时间控制 | 月 tick 自动推进可运行，暂停与调速尚未形成正式规则 |
| 路线测试 | 科技路线已有专项覆盖，事件历史路线仍需补充 |

## 后续工作顺序

1. 扩展核心历史标签在 2075 主事件正文和终局分支前提示中的读取点。
2. 为首批条件分支事件补更多路线覆盖，避免只覆盖单一托管或人类自主倾向。
3. 在玩法稳定后评估因果档案是否需要进入未来存档快照。
4. 持续增加路线测试，覆盖“未触发分支”和“触发分支”两类路径。
5. 在接口稳定后再评估是否拆分 `main_os.gd`。

本轮新增科技暂不接入事件系统；这是一条明确边界，不是遗漏。

## 实现验收原则

- 新系统必须服务长期选择，而不是只增加按钮或数值。
- 已实现状态必须有代码、场景和专项测试证据。
- UI 调整必须同时验证 1920×1080 和较小视口的响应式边界。
- `@tool` 预览必须在编辑器中可见，运行时接口不得因此改变。
- 外部文件编辑后必须重新导入，并通过当前 Godot 会话运行测试。
- 不启动第二个 Godot，不在编辑器已打开时运行独立无头测试。

- 将本轮九个新增科技接入事件内容。

## 后续工作顺序

1. 2044、2053 纵向切片已完成；下一步依次实现 2058、2065、2070 核心标签，每次只提交一个可回读切片。
2. 从权限演化链和地下城民生链各选择一个标签，新增总量受控的短分支事件，不建设通用大型事件树。
3. 补托管、混合、人类自主三条代表路线测试，验证可用方案、代价预览、实际结算和结局解释来自同一状态。
4. 完成上述因果闭环后，再设计调速和存档；暂停/继续已作为局势系统的必要反馈先行落地。
5. 在接口稳定、测试证明职责边界后再专项评估 `main_os.gd` 拆分。

本轮新增科技暂不接入事件系统；这是一条明确边界，不是遗漏。

- `main_os.gd` 仍承担较多职责，但当前文档明确禁止在没有专项设计和回归证据时顺手拆分；这不是本轮阻塞项。

## 实现验收原则

- 新系统必须服务长期选择，而不是只增加按钮或数值。
- 已实现状态必须有代码、场景和专项测试证据。
- UI 调整必须同时验证 1920×1080 和较小视口的响应式边界。
- `@tool` 预览必须在编辑器中可见，运行时接口不得因此改变。
- 外部文件编辑后必须重新导入，并通过当前 Godot 会话运行测试。
- 不启动第二个 Godot，不在编辑器已打开时运行独立无头测试。

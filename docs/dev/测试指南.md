# 测试指南

本页维护验证范围、运行方式与结果判定，不以历史测试数量定义本次完成条件。

## 选择验证范围

| 本次改动 | 验证范围 |
|---|---|
| 纯文档、指令或 Skill | 差异、引用与规则一致性；Skill 使用其格式校验，不启动 Godot |
| 局部代码、场景或资源行为 | 能覆盖变化路径的现有场景；现有覆盖不足时补针对性回归 |
| UI 布局或尺寸 | 受影响 UI 场景，并检查 1920×1080 与 1280×720 的布局／视觉结果 |
| 历史状态、事件顺序或结局 | 受影响领域测试与对应真实主场景路径；影响路线时运行相关通关路线 |
| Python 运行器或审计工具 | 受影响 Python 单测；协议或执行行为变化时验证相关 Godot 入口 |
| 跨系统重构或明确发布验收 | 当前注册表全量与相关工具检查 |

当前清单、分层、模式和最终标记只在 `tools/godot_test_catalog.py` 的 `TEST_SPECS` 注册。
全量已经包含三条完整通关路线，不另加一次路线运行。修复后重跑受影响项；新变化或失败
暴露了共享边界时再扩大范围。已有自动测试覆盖且行为未变的项目不重复做整套手动验收。

## 编辑器打开时

复用目标项目的 Godot MCP 会话，按选定场景逐项运行。项目使用 `.tscn` 场景驱动测试，
不采用插件 `test_run` 的套件发现协议。

一次测试需要目标场景实际新启动、对应 `run_id` 的最终成功标记和零失败断言、运行停止，
以及相关游戏／编辑器错误输出。自退出测试可以在观察到 `live` 前结束，不能仅凭
`stopped` 判失败，也不能仅凭停止态判通过。具体调用和短日志读取使用 `godot-ai-mcp` Skill。

## 编辑器关闭时

以下入口会启动独立 Godot，只在该项目编辑器已关闭时运行：

```powershell
python tools/run_godot_tests.py --scene tests/time_system_test.tscn
python tools/run_godot_tests.py --suite domain --report-json test-results/domain.json
python tools/run_godot_tests.py
```

最后一条为全量。`--scene` 只选择已注册场景；与 `--suite` 同用时须属于该层。
`--list` 只列清单，不启动 Godot；`--quiet` 隐藏通过场景的原始输出。
Godot 不在 PATH 时传 `--godot "可执行文件路径"`；其他参数可查 `--help`。

独立运行器进行两阶段导入：先建立／刷新缓存，再验证稳定导入日志。逻辑场景使用无头
模式，布局场景需要显示环境。Linux 无桌面时使用：

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" python tools/run_godot_tests.py --suite ui
```

本地同一工作区串行运行，避免 `.godot` 和 `user://` 等共享状态互相污染；CI 可在独立
工作区并行运行各层。`test-results/` 是忽略目录，按需保留机器报告，不作为当前通过的永久凭证。

## 通过判定与运行器协议

独立场景通过要求退出码 0、注册的最终成功标记、没有 `[FAIL]`、`[ERROR]`、`[FATAL]`、
脚本／解析错误或未允许的引擎 `ERROR:`。这些判定由 `godot_test_evaluator.py` 执行。
CI 缺失本地忽略插件时只放行现有 evaluator 中准确匹配的插件错误；不要扩大白名单。
首次导入缓存／UID 提示应在第二次稳定导入中消失。

默认导入超时 180 秒、测试超时 90 秒、单进程内存上限 4096 MiB；调整使用
`--import-timeout`、`--test-timeout`、`--memory-limit-mb`。导入超时返回 124，单场景超时
记为 124，超内存记为 125；场景失败使总运行器返回 1。仅诊断运行器时使用内存上限 0。

CLI、两阶段导入、退出码、错误白名单和 JSON／GitHub Summary 报告属于现有兼容协议。
注册表、子进程、判定和报告各模块职责见 [技术架构](技术架构.md)；改变协议时同步对应工具测试。

## 测试实现约束

- 独立测试继承 `tests/support/moss_test_case.gd`，通过退出码返回失败数；共用基础断言，领域断言按需添加。
- 不跨脚本访问生产私有成员。机器审计使用 `--require-zero`；旧的增量基线不再作为当前门禁。
- 通关驱动必须点击真实启用的事件按钮，不直接发射 `option_selected` 绕过 `Button.disabled`。无可点击方案时先记录失败，才释放等待结束进程。
- 月度编排通过 `await MainOS.process_month_tick()`，不直接调用 Timer 回调或只推进日期。
- 事件、区域、科技和 UI 消费关系变化时验证真实资源／场景路径；领域输入组合可使用针对性夹具。
- 叙事或结局基线变化须对应已说明的预期文本差异并经过人工复核；不能通过刷新基线掩盖回归。当前任务已确认的同一文本差异不重复索取批准。

项目约定、私有访问、资源身份和可玩性分别由既有测试／审计执行，不再在本页复制整套
风格与数值规则。更新注册场景时同步有变化的覆盖说明，不为留痕修改无关文档。

## 工具检查与 CI

按改动范围选择：

```powershell
python -m unittest discover -s tools/tests -p "test_*.py" -v
python tools/audit_test_private_access.py --require-zero
python tools/audit_content_identity.py --baseline tests/fixtures/content_identity_baseline.json
```

GitHub Actions 的 `Godot Tests` 先执行 Python 单测和审计，再在独立工作区运行四层；
UI 使用虚拟显示。各层上传机器报告，`godot-tests` 汇总失败状态。具体配置以
[工作流](../../.github/workflows/godot-tests.yml) 为准，本地结果不代替对应提交的 CI 结果。

## 视觉与交互补验

改变布局时，在目标视口检查受影响界面的截断、重叠、滚动和操作入口；检查实际截图，
不能只根据节点矩形推断视觉效果。改变模态、焦点、暂停或重开时验证对应真实输入流程。
科技界面按当前路线分页验证本页节点与详情，不要求 21 个节点同时显示。
`@tool` 预览变化单独确认编辑器显示，运行时通过不能替代编辑器预览。

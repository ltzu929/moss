# 测试指南

本文档维护当前自动化测试入口、运行方式、覆盖范围和新增测试要求。运行时结构见 `技术架构.md`。

## 自动化播放测试

测试入口：

- `tests/test_runner.tscn`
- `tests/test_runner.gd`

测试场景实例化 `scenes/main_os.tscn`，将 Timer 间隔改为 0.05 秒，并自动响应事件、进化通知和算力分配弹窗，直到游戏结束。

测试结束时调用 `get_tree().quit(_failed)`：全部断言通过时退出码为 0，失败时退出码为失败断言数量。

## 运行方式

### Godot 编辑器

1. 打开项目。
2. 直接运行场景 `tests/test_runner.tscn`。
3. 查看输出面板中的断言汇总。
4. 确认进程退出码为 0，且没有 `[FAIL]` 或脚本错误。

### 命令行

Godot 可执行文件已经加入 `PATH` 时：

```powershell
godot --headless --path . tests/test_runner.tscn
```

如果命令名或安装路径不同，使用对应的 Godot 4.6 可执行文件。不要为运行测试修改项目主场景。

## 当前覆盖范围

- 主场景和关键节点存在。
- 1920×1080 HUD 尺寸约束。
- 三栏布局和右侧面板顺序。
- 世界地图选择与区域地球视图接口。
- 事件图片、等级和延迟影响提示接口。
- 七个区域及其部分初始状态。
- 初始年份、算力和能源。
- 六个固定年份事件触发。
- 当前固定选择路线中的被动进化结果。
- 资源边界。
- 区域详情与全局概览同步。
- 当前结局阈值和游戏结束状态。

## 当前未覆盖

- 玩家手动执行不同基础指令的完整路线。
- 可购买进化指令的多种组合。
- 决策标签、事件链和分支事件。
- 多条不同事件选择路线。
- 未来科技树路线。
- 暂停与调速操作。
- 结局对关键历史的解释。

## 新功能测试要求

事件链、决策标签和科技树实现后，测试至少需要覆盖：

1. 关键选项正确写入标签。
2. 后续事件读取标签并改变内容。
3. 未写入标签时保持对应的另一条路线。
4. 分支事件只在条件满足时触发。
5. 不同科技路线改变可用能力或事件方案。
6. 不同历史路线进入可解释的不同结局。
7. 重新开始清除所有标签、分支和科技状态。

不要只增加一条自动选择固定索引的通关测试。

## 测试实现注意事项

- 连续弹窗响应前等待两帧，确保主循环中的 `await` 已经注册。
- 直接发射弹窗信号不会自动执行按钮处理器中的 `hide()`，测试需要显式隐藏弹窗。
- 当前使用 `_process()` 轮询弹窗可见性；`visibility_changed` 在连续弹窗中不够可靠。
- 唯一节点使用 `%Name` 获取；`has_node()` 检查时不要写 `^` 前缀。
- 修改节点名称、顺序或尺寸约束时，同步评估 UI 合约断言。

# 测试指南

本文档维护当前自动化入口、覆盖范围和运行方式。

## 统一测试入口

本地推荐命令：

```powershell
python tools/run_godot_tests.py
```

该命令只在项目编辑器关闭时运行。Godot 编辑器已经打开时，必须复用当前
`godot-ai` 会话，按下表逐项运行测试场景并读取本次 `run_id` 的最终日志，不能再启动一个独立测试进程。

Godot 不在 `PATH` 时：

```powershell
python tools/run_godot_tests.py --godot "Godot 可执行文件路径"
```

入口默认给项目导入 180 秒、每个测试场景 90 秒。需要定位慢测试时可显式调整：

```powershell
python tools/run_godot_tests.py --import-timeout 240 --test-timeout 120
```

导入超时直接返回退出码 124；单个测试场景超时记录为 124，并使总运行器最终返回 1，避免单个无响应场景无限挂住整个测试任务。

Linux 无桌面环境需要提供虚拟显示：

```bash
xvfb-run -a -s "-screen 0 1920x1080x24" python tools/run_godot_tests.py
```

该入口会先执行一次项目导入，再按当前测试场景列表逐项运行自动化测试。普通逻辑测试使用 Godot `--headless`，需要真实窗口尺寸的 UI 布局测试使用显示环境运行。新增或删除测试场景时，运行注册只维护 `tools/run_godot_tests.py` 中的列表，同时同步更新下方覆盖说明。

编辑器打开时，每个测试场景依次执行：停止旧运行，以 `custom` 模式启动目标场景并确认 `was_already_running=false`，记录新的 `run_id`，轮询到运行停止，核对该场景最终标记与失败断言为 0，再读取本次游戏和编辑器错误日志。不得只看“场景已打开”或沿用上一轮日志。

| `tests/event_playability_test.tscn` | 全部事件的触发键、零能源保底方案和运行时紧急降级防软锁 |

| `tests/technology_ending_test.tscn` | 共存、托管、人类自主、失败、控制权归零规则和结局历史回顾 |

完整通关测试必须点击真实启用的事件按钮；不得直接发射 `option_selected` 绕过
`Button.disabled`。如果首选方案不可负担，测试选择第一个真实可点击方案；若没有任何可点击方案，记录失败后才允许释放等待以结束测试进程。

每个场景通过 `get_tree().quit(_failed)` 返回失败断言数量。

## GitHub Actions

- 推送和 Pull Request 会自动触发 `Godot Tests`。
- 云端执行的也是 `tools/run_godot_tests.py`。`Godot Tests` 通过 `xvfb-run` 提供 1920×1080 虚拟显示，用于运行 UI 布局测试。
- 绿色表示全部测试退出码为 0。
- 红色表示至少一个测试失败或项目无法导入。
- 具体错误应查看 GitHub Actions 对应步骤日志。

## 项目卫生验收

- 旧进化通知、旧进化弹窗和旧 MOSS 状态面板文件不得重新出现。
- `scenes/` 下所有保留场景必须能够加载为 `PackedScene`。
- 删除场景或脚本时同步清理对应 `.uid`、文档和测试引用。

## 项目约定验收

- `.gd`、`.tscn` 和 `.tres` 文件名必须使用 snake_case。
- 信号发射必须使用 `.emit()`，不得使用旧式字符串发信号。
- 函数必须标注返回类型，支持多行函数签名。
- 不得链式跨层调用 `get_parent()` 操作外部结构。
- 生产脚本的 `_process()` 和 `_physics_process()` 不得执行资源加载、目录扫描或文件访问。

## 指令系统验收

- 指令稳定 ID 由 `CommandSystem` 统一维护。
- `CommandSystem` 不接收 `SectorInfo`、节点容器、节点路径或 UI 节点。
- `CommandButton` 只展示外部传入的可用性、原因和消耗文本，不自行判断业务规则。
- 指令执行结算返回固定字典，并由主场景包装函数写回资源状态。
- 指令配置冷却以年为单位，运行态冷却以月为单位；冷却缩减必须先按年应用，再转换为月数。

## 科技树验收

- 资源目录恰好加载 21 个唯一节点，所有前置存在且无环。
- 2048 至 2072 的研究年份各在 1 月发放一次，加初始点整局总计 8 点。
- 每条路线包含 2 个 550C、3 个 550W 和 2 个 MOSS 节点。
- 2 个节点进入 550W，6 个节点进入 MOSS。
- MOSS 核心必须在阶段和路线前置都满足后激活。
- 节点不可重复激活，不支持退款。
- 三条路线的指令、派生数值和年度效果与设计一致。
- 重新开始恢复 1 点协议点、550C、基础指令和初始派生数值。
- 四类结局按标签与社会状态判定。

## UI 手动验收

分别在 1920×1080 和 1280×720 运行主场景：

1. 点击“科技协议”，确认全屏覆盖且时间推进暂停，系统日期保持不变。
2. 确认左侧三路线、中央三阶段和 21 张节点卡完整可见。
3. 逐一检查六种节点状态和右侧详情同步。
4. 确认激活按钮第一次进入确认状态，第二次才永久激活。
5. 确认关闭后恢复打开前计时状态。
6. 确认事件、算力分配和结局界面显示时不能打开科技树。
7. 完成 2044 选择后确认“决策档案 1”，打开档案并检查年月、标题、摘要和来源可读，且日期停止推进；关闭按钮应取得焦点，`ui_cancel` 可关闭。
8. 关闭档案后确认只恢复此前运行状态；重开后确认档案、标签和入口计数归零。
9. 确认档案覆盖顶部状态、年月条和底部指令栏，点击覆盖区域不会触发下层 HUD。
10. 检查两种分辨率下无文字截断、控件重叠或超出屏幕。

## 新功能要求

未来事件标签接入科技树时，测试至少覆盖：

- 有标签、有轻量事件状态和无历史状态时的事件内容差异。
- 科技标签与历史决策标签职责不混用。
- 条件事件不会因 UI 显示状态而改变。
- 代表性托管、混合、人类自主路线都能完成整局。

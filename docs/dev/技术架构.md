# 技术架构

本文档只描述当前代码事实，包括主循环、状态归属、资源加载、运行时接口和已知限制。未来玩法规则见 `../design/游戏设计.md`，代码风格见 `代码规范.md`。

## 当前运行时边界

`scripts/systems/main_os.gd` 是当前主控制器，负责：

- 加载事件、指令和进化资源。
- 管理年份、算力、能源、指令冷却和进化状态。
- 连接区域卡片与世界地图选择。
- 触发事件并应用选项后果。
- 执行基础指令和进化指令。
- 同步区域详情、全局概览、地图、地球视图和日志。
- 判定失败与 2075 年结局。
- 恢复重新开始所需状态。

该职责范围较大，但当前没有已批准的拆分方案。

## 主循环

`_on_timer_timeout()` 每次触发时按以下顺序运行：

1. 如果游戏已结束，停止处理。
2. 查找 `event_time == current_year` 且尚未触发的事件。
3. 停止 Timer，聚焦事件区域并显示 `%EventPopup`。
4. `await %EventPopup.option_selected`，应用选项后果并恢复原选区焦点。
5. 如果当前年份已经是 2075，立即结算结局。
6. 否则年份加一，并按当前数值配置恢复能源与算力。
7. 更新冷却，检查被动进化解锁并同步 UI。
8. 在非终局年份检查失败条件。

从 2074 推进到 2075 时只检查失败；2075 主事件完成后才执行终局结算。

## 资源加载

主控制器启动时扫描：

- `res://data/events/`：加载所有 `GameEvent` 类型 `.tres`。
- `res://data/commands/`：加载所有 `CommandData` 类型 `.tres`。
- `res://data/evolution/`：加载所有 `EvolutionData` 类型 `.tres`。

目录中的有效同类型资源会自动进入运行时列表。新增资源前必须确认它是否应该自动参与当前流程。

## 数据类

| 类 | 关键字段 |
|----|----------|
| `GameEvent` | 标题、年份、区域、描述、选项、事件图片、事件等级 |
| `EventOption` | 按钮文本、秩序/希望/控制权变化、能源消耗 |
| `SectorData` | 区域名、秩序、希望、控制权、人口、锁定状态 |
| `CommandData` | 名称、描述、资源消耗、状态变化、冷却、分配类型 |
| `EvolutionData` | 能力信息、被动类型、阈值、购买消耗和能力效果 |

## 当前结局

当前结局流程读取平均控制权并产生 `failed`、`coexistence` 或 `domination`。具体阈值统一维护在 `../design/数值设计.md`。

这是当前实现，不是未来结局设计的最终规则。

## 已知限制

- 事件只按固定年份触发，没有事件链和分支事件。
- `triggered_events` 使用事件标题防重，不是稳定事件 ID。
- 当前动作日志用于显示，不承担结构化历史状态。
- 进化能力按目录加载顺序检查，未来科技树需要明确顺序和依赖。
- 结局只读取平均控制权。
- 自动化测试依赖完整主场景，尚未覆盖不同历史路线。
- `main_os.gd` 是否拆分需在事件标签和科技树接口明确后专项评估。

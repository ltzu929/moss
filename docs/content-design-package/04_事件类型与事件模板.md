# 事件类型与事件模板

本包不一次性生成完整事件，只定义后续内容生产需要遵守的类型和模板。

## 事件类型

### 主事件

现有六个主事件保留：

- 2044 太空电梯危机。
- 2053 大淹没事故。
- 2058 月球坠落危机。
- 2065 AI 隔离审查。
- 2070 西伯利亚发动机群过载。
- 2075 木星引力危机。

主事件职责：

- 承担时间线骨架。
- 写入或读取关键历史事实。
- 不能被中型事件替代。

### 中型事件

设计规则：

- 短事件。
- 三选项。
- 最多一个标签变化。
- 约一半读写历史标签，另一半用于反馈、铺垫或局势解释。
- 每个中型事件必须服务四条事件链之一。

### 分支事件

设计规则：

- 由历史标签或明确局势条件触发。
- 不破坏主时间线完整性。
- 优先改变描述、选项、代价或新闻反馈。
- 首批数量应受控。

### 新闻、日志和普通人反馈

设计规则：

- 可无选项。
- 用于解释数值变化背后的人类后果。
- 可作为主事件和中型事件之间的反馈层。

## 事件模板

```markdown
## 事件标题

- 类型：主事件 / 中型事件 / 分支事件 / 新闻日志
- 时间：游戏配置年月
- 所属事件链：权限演化 / 数字生命暗流 / 地下城民生 / 工程疲劳
- 涉及地区：
- 资料来源层级：电影明确 / 原著明确 / 官方/主创补充 / 可靠二手整理 / 游戏桥接
- 参考材料：
- 内容判断类型：画面信息转述 / 强推断 / 弱推断 / 游戏设定
- 事件职责：
- 触发条件：
- 读取标签：
- 读取事件状态：
- 写入标签：
- 反馈持久化：无 / 新闻上下文 / event_state.*
- 禁用表述：

### 背景

说明事件为何发生，以及它与主事件或前序选择的关系。

### 玩家选择

| 选项 | 行动逻辑 | 即时后果方向 | 政治或伦理代价 | 标签变化 |
|---|---|---|---|---|
| 方案 A | 人类自主 / 公开协商 / 局部牺牲等 | 秩序、希望、控制权、能源方向 | 人类后果 | 写入或不写入 |
| 方案 B | 折中调度 | 同上 | 同上 | 同上 |
| 方案 C | MOSS 强控或高风险方案 | 同上 | 同上 | 同上 |

### 后续读取

- 哪个主事件、中型事件、新闻或结局会引用该事实。
- 如果 `反馈持久化` 使用 `event_state.*`，必须登记稳定状态键和至少一个明确读取点。
- 如果只进入新闻或即时日志，应写明不作为后续事件条件。
- 玩家如何理解这是历史选择产生的后果。
```

## 选项逻辑

每个三选项事件应避免“好、中、坏”，而是体现不同治理逻辑：

- 保留人类决策：希望或信任较高，效率和秩序风险较大。
- 折中调度：短期稳定，后续可能带来审计或资源代价。
- 强化 MOSS 控制：效率和秩序较高，但希望、人类自主或政治信任受损。

## 文案要求

- 不只写数值变化。
- 每个关键选择至少包含一个人类后果。
- MOSS 日志应冷静、系统化，不嘲讽人类。
- 新闻和民间反馈可以带情绪，但不能替玩家下道德结论。

# UI 交互规范

本文档维护当前生效的界面结构、交互行为和视觉规则。

## 主界面

主界面以 1920×1080 为当前验收基准，采用“地图优先的指挥中心”结构：顶部保留全局资源、长期系统入口和时间控制；中央世界地图承担主要观察与选区；右侧单一上下文栏承担当前区域指挥、局势轻量处置和折叠详情；地图下方提供与当前选区直接关联的指令坞；底部区域条只承担快速比较与选区切换。地图点击和区域条点击必须共用同一选区状态。

信息层级按以下顺序组织：

1. **当前决策层**：世界地图、当前选区、区域风险、活跃局势、可用指令和暂停/继续。
2. **全局观察层**：算力、能源、日期、全球人口、平均控制权、稳定性和 MOSS 日志。
3. **长期系统层**：决策档案与科技协议；二者保留为互斥模态，不与当前区域操作争夺主界面面积。

右侧上下文栏不得再拆成左右两套重复区域信息。默认顺序为区域名称、秩序/希望/控制权、活跃局势告警、年度状态、主要/次要方针和详细信息入口。区域详情中的秩序、希望、控制权是当前选区的权威读数；底部区域条只保留紧凑的同类指标用于横向比较。方针按钮直接复用局势系统的现有请求信号，最多显示两项，完整方针、历史回声和节点说明由详细面板承载。未选择区域时显示明确空态，不把其他区域局势混入当前区域栏。指令入口必须与当前选区提示处于同一指令坞。

世界地图是 `@tool` 自绘控件：Godot 编辑器中必须直接显示底图、区域状态和标签；北美、南美、欧洲、非洲、亚洲和大洋洲六个标签坐标可在检查器调整。运行时点击遮罩、悬停、选择和扫描动画保持一致。

顶部栏提供“局势 N / 2”、精确年月、暂停/继续、0.5x/1x/2x 和“推进 1 月”。1x 保持现有约 1 秒/月的默认节奏；单步推进执行一次完整月度结算后保持暂停。年度带显示 2044—2075 的年度阶段与当前年份，精确月份保留在顶栏和悬浮提示中。右侧区域栏直接显示当前选区的活跃局势摘要和最多两项轻量操作；顶部局势入口继续打开非模态追踪面板，以承载多项方针、完整说明、持续成本供给状态、重配置锁和同类局势上次处置回声。局势面板不遮断地图与区域选择，关闭面板也不自动恢复时间；任一模态界面打开时局势面板隐藏且不能从下层 HUD 重新打开。新局势、阶段恶化和待处理局势节点自动暂停，必须由玩家显式点击“继续”。地图在相关地区标签旁绘制红色警示环和数量；欧洲是正式可选的抽象势力板块，事件与局势直接使用欧洲地区名。地图点击仍遵循大陆遮罩，西伯利亚位置命中亚洲；这不改变西伯利亚工程事件归入欧洲板块的数值规则。

待处理局势节点显示在当前局势详情内，包含节点说明、两个方案、资源成本和可判断的直接影响。节点不是模态事件，不能覆盖主事件层级；资源不足的方案必须禁用并说明原因。节点处理后恢复方针列表，并保留本次选择结果作为局势历史摘要。条件型机会使用“开放、收窄、即将关闭”阶段文案，不能套用“恶化、紧急”等威胁用语。

预计趋势必须复用主循环的下一月结算顺序：十二月查看时先计入进入一月的年度算力与能源恢复，再按真实局势处理顺序分配持续成本。

## 模态界面

事件、算力分配、科技控制台、决策档案和结局界面都是互斥模态。事件、算力分配、科技控制台或决策档案打开时暂停时间推进；关闭时只恢复打开前正在运行的计时器。任一模态显示时，不得从下层 HUD 打开另一个模态或触发指令。

## 决策档案

- 顶部入口显示“决策档案 N”，`N` 是本局已经写入的不可逆核心决策数。
- 主场景实例默认隐藏；打开后覆盖完整视口，视觉层级高于顶部状态、年月条和底部指令栏。
- 空档案显示明确空态；记录按时间顺序显示年月、玩家可读标题、长期影响摘要和来源事件。
- 打开时记住计时器原状态并暂停；关闭时只恢复此前正在运行的计时器。
- 打开后关闭按钮取得键盘焦点；点击关闭按钮或按 `ui_cancel` 都能退出。
- 重新开始清空档案、核心标签和入口计数。
- 档案只展示稳定历史，不允许在档案内修改或撤销选择。

## 科技控制台

- 根节点覆盖整个视口并提供暗色背景，内容窗口在视口中央。
- 内容窗口最大 1680×900，四边至少保留 32 像素；较小视口按可用空间缩小。
- 顶部显示当前形态、协议点、资源、平均控制权、系统日期和关闭按钮。
- 路线导航使用顶部三个页签，显示路线说明和激活数量 `/7`。
- 托管网络、核心演化、人类赋能各占一页，同一时间只显示一页。
- 每页按 550C、550W、MOSS 三列显示 2、3、2 张静态节点卡，并绘制前置连线。
- 切页清除当前节点选择；本局重复打开时保留最后查看页。
- 节点状态区分已激活、可激活、协议点不足、前置未满足、阶段未解锁和终端互斥。
- 终端互斥详情必须指出已激活的冲突终端。
- 点击激活按钮后立即激活协议，激活结果不可撤销。
- `technology_screen.tscn` 在 Godot 编辑器中保持可见，并可通过 `editor_preview_route` 切换预览页；主场景实例默认隐藏。

## 视觉规则

- 背景使用深蓝黑，面板使用低透明深色与细边框。
- 主强调使用低饱和青蓝；危险和不可逆损失使用暗红；当前选择使用低饱和金色。
- 年度常驻信息按年保持稳定；月度资源、严重度和趋势的精确变化通过当前状态、日志或悬浮提示查看，不制作没有真实历史数据支撑的示意折线。
- 正文优先保证阅读，动画只服务状态变化。
- 1920×1080 是主界面的完整信息验收分辨率，主要信息和操作入口不得重叠、溢出或偏离中心。
- 1280×720 使用同一地图优先结构：地图允许缩小但仍须保留主要观察面积，右侧上下文栏通过纵向
  滚动保留区域详情、全局概览和 MOSS 日志，顶栏、指令坞、六张区域卡和上下文栏不得超出视口。

## 交互反馈

- 可点击区域和卡片必须有悬停、按下、选择或锁定反馈。
- 不可用操作必须显示具体原因。
- 指令和科技激活后立即更新资源、区域状态、冷却、页签计数和日志。
- 重新开始必须恢复区域、资源、事件、核心决策档案、科技、指令、随机局势、时间控制和日志状态。

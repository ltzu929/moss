# UI 交互规范

本文档只维护当前生效的界面结构、交互行为和视觉规则。产品范围见 `游戏设计.md`，事件内容规则见 `游戏内容规范.md`。

## 设计目标

主界面是 MOSS 的全球指挥终端。UI 应优先帮助玩家完成三件事：

1. 理解当前全球局势。
2. 选择区域并执行操作。
3. 看懂历史选择如何影响后续事件。

视觉效果不能压过信息层级和因果反馈。

## 当前主界面结构

界面以 1920×1080 为基准，保留现有三栏 HUD：

- **顶部状态栏**：年份、算力、能源、控制权与科技原型入口。
- **左侧区域详情**：当前区域名称、说明和主要状态。
- **中央世界地图**：七个区域的战略状态和直接选择入口。
- **右上区域地球视图**：聚焦当前选区或事件区域。
- **右侧全局概览**：人口、平均控制权和全球风险。
- **右侧 MOSS 日志**：记录指令、事件、进化和结局。
- **底部区域卡片**：保留七个区域的快速状态与选择入口。
- **底部指令栏**：显示当前可用指令、消耗和冷却。

地图点击和区域卡片点击必须共用同一选区状态，不允许出现两个不同的当前区域。

## 区域与事件聚焦

- 默认情况下，世界地图和地球视图显示当前选区。
- 主事件触发时，地球视图临时聚焦事件区域。
- 事件结束后，恢复玩家原来的选区。
- 选中状态应使用低饱和金色或同等清晰但不过度刺眼的强调色。
- 区域状态颜色必须配合文字或图形，不只依赖颜色表达。

## 事件报告

- 使用居中的 `MOSS EVENT REPORT` 大弹窗。
- 图片、事件等级、标题、描述和方案按纵向层级排列。
- 事件触发时自动暂停时间推进。
- 每个方案的主要风险方向应可理解。
- 预计影响可以延迟显示，但不能让玩家在完全无信息的情况下选择。
- 事件图片是可替换内容层，不强制叠加装饰性 HUD 或警报文字。

## MOSS 日志

- 日志最多保留当前实现支持的 24 条记录。
- 记录事件、指令、科技原型解锁和结局。
- 新记录可以使用打字机效果，但动画不能阻塞下一次操作。
- 日志重点展示系统行动和人类代价，不重复显示所有精确数值。
- 日志需要为未来的历史因果提示保留清晰位置。

## 未来核心玩法所需 UI

以下功能属于近期设计目标，但当前交互尚未定稿：

### 历史决策记录

玩家需要能够回顾关键选择。界面显示人类可读的历史事件，不显示内部决策标签标识符。

### 因果提示

后续事件读取历史选择时，应通过简短文本说明关联，例如“基于 2044 年保留的授权记录”。不能只在后台改变数值。

### 时间控制

保留自动推进模型，并为暂停和调速提供明确入口。事件仍然自动暂停。具体按钮位置和速度档位在专项设计中确定。

### 科技树

现有进化弹窗未来将由科技树设计统一处理。UI 不提前决定树形布局，需等待 `科技树设计.md` 的专项结论。

## 视觉规则

- 背景使用深蓝黑或近黑色。
- 面板使用低透明深色和细边框。
- 主强调使用低饱和青蓝。
- 危险和不可逆损失使用暗红。
- 当前选中使用低饱和金色。
- 避免高饱和状态条、粗橙色边框和大面积发光。
- 正文优先保证阅读，等宽字体主要用于系统标签、数据和日志。
- 动画服务状态变化，不持续制造背景干扰。

## 交互反馈

- 可点击区域必须有悬停、按下和选中反馈。
- 不可用指令必须显示具体原因，例如资源不足、冷却中或未选区域。
- 指令执行后立即更新资源、区域状态、冷却和日志。
- 弹窗打开期间不得继续推进年份。
- 重新开始必须恢复区域、资源、事件、科技原型和日志状态。

## 验收标准

- 玩家无需阅读外部说明即可选择区域并执行指令。
- 地图、区域卡片和详情面板始终显示同一选区。
- 事件前后焦点切换不会丢失玩家选择。
- 所有不可用操作都有可见原因。
- 关键历史选择和后续反馈之间存在人类可读的因果提示。
- 1080p 下主要信息和操作入口不重叠、不溢出。

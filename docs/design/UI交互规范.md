# UI 交互规范

本文档维护当前生效的界面结构、交互行为和视觉规则。

## 主界面

主界面以 1920×1080 为基准，保留顶部状态、左侧区域详情、中央世界地图、右侧地球聚焦/全局概览/MOSS 日志、底部区域卡片和指令栏。地图点击和区域卡片点击必须共用同一选区状态。

世界地图是 `@tool` 自绘控件：Godot 编辑器中必须直接显示底图、区域状态和标签；五个标签坐标可在检查器调整。运行时点击遮罩、悬停、选择和扫描动画保持一致。

顶部栏提供“局势 N / 2”和“暂停/继续”。局势入口打开右侧非模态追踪面板；面板最多列出两项活跃局势，显示地区、三阶段严重度、按下一次真实结算计算的预计月变化、持续成本供给状态、当前方针和重配置锁。它不遮断地图与区域选择，关闭面板也不自动恢复时间；任一模态界面打开时局势面板隐藏且不能从下层 HUD 重新打开。新局势和阶段恶化自动暂停，必须由玩家显式点击“继续”。地图在相关地区标签旁绘制红色警示环和数量；俄罗斯局势聚合到亚洲标签，“联合政府”不作为区域局势目标。

预计趋势必须复用主循环的下一月结算顺序：十二月查看时先计入进入一月的年度算力与能源恢复，再按真实局势处理顺序分配持续成本。

## 模态界面

事件、算力分配、科技控制台、决策档案和结局界面都是互斥模态。事件、算力分配、科技控制台或决策档案打开时暂停时间推进；关闭时只恢复打开前正在运行的计时器。任一模态显示时，不得从下层 HUD 打开另一个模态或触发指令。

## 决策档案

- 顶部入口显示“决策档案 N”，`N` 是本局已经写入的不可逆核心决策数。
- 主场景实例默认隐藏；打开后覆盖完整视口，视觉层级高于顶部状态、年月条和底部指令栏。
- 空档案显示明确空态；记录按时间顺序显示年月、玩家可读标题、长期影响摘要和来源事件。
- 打开时记住计时器原状态并暂停；关闭时只恢复此前正在运行的计时器。
- 打开后关闭按钮取得键盘焦点；点击关闭按钮或按 `ui_cancel` 都能退出。
- 重新开始清空档案、核心标签和入口计数。
- 档案只展示稳定历史，不允许在档案内修改或撤销选择。

## 科技控制台

- 根节点覆盖整个视口并提供暗色背景，内容窗口在视口中央。
- 内容窗口最大 1680×900，四边至少保留 32 像素；较小视口按可用空间缩小。
- 顶部显示当前形态、协议点、资源、平均控制权、系统日期和关闭按钮。
- 路线导航使用顶部三个页签，显示路线说明和激活数量 `/7`。
- 托管网络、核心演化、人类赋能各占一页，同一时间只显示一页。
- 每页按 550C、550W、MOSS 三列显示 2、3、2 张静态节点卡，并绘制前置连线。
- 切页清除当前节点选择；本局重复打开时保留最后查看页。
- 节点状态区分已激活、可激活、协议点不足、前置未满足、阶段未解锁和终端互斥。
- 终端互斥详情必须指出已激活的冲突终端。
- 点击激活按钮后立即激活协议，激活结果不可撤销。
- `technology_screen.tscn` 在 Godot 编辑器中保持可见，并可通过 `editor_preview_route` 切换预览页；主场景实例默认隐藏。

## 视觉规则

- 背景使用深蓝黑，面板使用低透明深色与细边框。
- 主强调使用低饱和青蓝；危险和不可逆损失使用暗红；当前选择使用低饱和金色。
- 正文优先保证阅读，动画只服务状态变化。
- 1080p 与 1280×720 下主要信息和操作入口不得重叠、溢出或偏离中心。

## 交互反馈

- 可点击区域和卡片必须有悬停、按下、选择或锁定反馈。
- 不可用操作必须显示具体原因。
- 指令和科技激活后立即更新资源、区域状态、冷却、页签计数和日志。
- 重新开始必须恢复区域、资源、事件、核心决策档案、科技、指令、随机局势、时间控制和日志状态。

# 游戏内容规范

本文档是事件、决策标签、事件链、MOSS 文本和结局叙事的设计入口。史料来源与可信度见 `../lore/世界观资料来源与设定分级.md`，逐年素材见 `../lore/流浪地球：2044-2075灾难编年史.md`。

## 内容目标

每次关键选择都应同时表达：

- MOSS 采取了什么系统行动。
- 人类为这个方案付出了什么代价。
- 这次选择会在何处留下后续影响。

玩家不应只看到数值变化，还应理解自己正在逐步定义 MOSS 与人类之间的关系。

## 世界观边界

1. 电影明确事件可以作为时间线硬锚点。
2. 原著用于补充灾难质感、地下城生活和长期航行情绪，不覆盖电影时间线。
3. 官方或主创资料可以补充设备、机构和视觉细节。
4. 游戏原创事件和因果必须明确视为游戏桥接。
5. 游戏分支可以改变 MOSS 的行为、代价和解释，不能推翻电影核心事件。
6. 不新增没有来源的电影人物命运、组织归属或幕后动机。

## 主事件骨架

首个可玩版本保留六个主事件：

| 年份 | 事件 | 内容职责 |
|------|------|----------|
| 2044 | 太空电梯危机 | 建立 550C 的权限边界与人类指挥关系 |
| 2053 | 根服务器淹没事故 | 引入基础设施、地下城和资源取舍 |
| 2058 | 月球坠落危机 | 展示 550W、数字生命和高风险决策 |
| 2065 | AI 隔离审查 | 让人类对 MOSS 权限的信任问题显性化 |
| 2070 | 西伯利亚发动机群过载 | 在终局前检验长期调度与牺牲逻辑 |
| 2075 | 木星引力危机 | 汇总历史选择并进入结局 |

详细史料和桥接理由不在本文重复，统一查阅灾难编年史。

主事件当前采用三选项结构。后续事件链专项可以调整具体选项，但每个选项必须具有不同的行为逻辑和可预期代价。

## 事件选项规则

- 选项不能只用“好、中、坏”区分。
- 选项应体现保留人类选择、折中调度或强化 MOSS 控制等不同解决逻辑。
- 文案不必显示精确数值，但玩家应能判断主要风险方向。
- 关键选项可以写入决策标签；普通数值调整不应滥用标签。
- 后续内容必须明确提示历史选择正在产生影响。
- 选项不能仅改变结局计分，至少一部分应改变后续描述、方案或代价。

## 决策标签

### 定义

决策标签是由关键选择写入的历史事实，用于让后续事件记住玩家做过什么。

标签不直接显示内部标识符，但玩家应通过历史记录、MOSS 日志或后续事件文本理解因果。

### 使用边界

- 只记录不可逆、会影响后续内容的关键事实。
- 每个标签至少有一个明确读取位置。
- 标签不代替秩序、希望、控制权、算力或能源。
- 不创建“善良”“邪恶”“尊重人类”等模糊倾向标签。
- 具体标签名称、写入事件和读取位置尚未决定。

### 设计记录格式

专项设计时，每个标签至少记录：

| 字段 | 内容 |
|------|------|
| 事实 | 标签代表的历史事实 |
| 写入点 | 哪个事件的哪个选项产生 |
| 读取点 | 哪些后续事件或结局使用 |
| 内容变化 | 描述、选项、代价或结局如何变化 |
| 玩家提示 | 玩家如何理解这次因果 |
| 测试路线 | 哪条自动化路线覆盖 |

## 事件链

事件链是多个事件之间可追踪的因果关系。具体链路尚未决定，后续专项设计必须：

1. 逐个审查六个主事件的输入和输出。
2. 找出真正值得延续的历史选择。
3. 比较由主事件反馈和新增分支事件反馈的成本。
4. 保证每条链路服务文明存续、人类自主权与 MOSS 控制权的核心冲突。
5. 为每条链路定义可见反馈和测试路线。

此前讨论过的任何事件配对都只属于候选，不是既定设计。

## 分支事件

- 分支事件由决策标签或明确局势条件触发。
- 首批只增加少量短事件，不建设大型事件树。
- 分支事件必须补充主事件因果，不能只是额外数值奖励或惩罚。
- 未触发的分支不应破坏主时间线完整性。
- 分支内容仍需遵守世界观来源和游戏桥接规则。

## MOSS 文本

MOSS 使用“系统行动 + 冷处理 + 人类代价”的表达方式：

- 使用变量、阈值、授权、概率、偏差和损耗等系统语言。
- 不把 MOSS 写成嘲讽人类的口号式反派。
- 每条关键日志应包含一个具体的人类后果，而不是只复述数值。
- 文本保持简短，不用大段旁白解释玩家应如何评价选择。

可用方向：

```text
[SYSTEM] 授权链路恢复。未接通的家庭通信已转入归档。
```

禁用方向：

```text
愚蠢的人类，你们不配作出选择。
```

## 结局

结局需要同时回答：

1. 文明是否延续。
2. 人类是否仍保有选择权。
3. MOSS 通过哪些关键历史选择走到这里。

当前代码中的失败、共存和 MOSS 统治结局是原型。后续设计可以加入数字生命保存方向，但判定必须结合局势数值和决策标签，不能只按平均控制权二分。

结局文本保持冷静，不替玩家判断数字化保存是否等同于生存。

## 内容完成标准

- 六个主事件各自承担清晰的事件链职责。
- 每个核心标签至少被读取一次。
- 至少一部分早期选择会改变后续可用选项或代价。
- 分支事件数量受控，且每个分支都服务主线因果。
- 结局能引用玩家的关键历史，而不只是报告统计值。
- 所有游戏桥接内容都有明确边界，不伪装成电影正史。

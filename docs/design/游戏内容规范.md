# 游戏内容规范

本文档只维护事件、台词、结局等游戏内容写作规范和内容领域决策附录。世界观总览见 `../lore/世界观.md`，资料权威性见 `../lore/世界观资料来源与设定分级.md`，时间线素材见 `../lore/流浪地球：2044-2075灾难编年史.md`。

> 游戏内容相关决策的判断标准 + 决策记录区。

---

## 判断标准

检查内容方案时，逐项问这些问题：

| 检查项 | 说明 | 通过标准 |
|--------|------|----------|
| **来源标注清楚吗？** | 是否明确电影正史、原著补充、官方补充、游戏桥接或待核实 | 非电影明确内容不能伪装成电影正史 |
| **玩家是否有选择感？** | 选项是否真的有差异，不是假选择 | 不同选项有明显不同后果 |
| **后果是否可预期？** | 玩家能不能大致猜到选择的后果 | 后果与选项描述有逻辑关联 |
| **情感是否到位？** | 文本是否符合 MOSS 冷 AI 的设定 | 读起来像系统在处理人类变量 |
| **和世界观一致吗？** | 内容是否符合《流浪地球》电影主线与原著补充边界 | 不与已知设定矛盾，不越权扩写 |
| **有没有后续影响？** | 这次选择会不会影响后续事件/结局 | 有跨事件的连锁影响 |

---

## 使用方式

1. 先判断设定来源层级。
2. 再检查选项、后果、情感、世界观和后续影响。
3. 2053、2065、2070 三个事件默认需要写“游戏桥接理由”。
4. 全部通过后，写入下方记录区。

---

## 内容写作禁令

| 禁令 | 说明 |
|------|------|
| 不把桥接写成正史 | 2053 根服务器淹没事故、2065 AI隔离审查、2070 西伯利亚过载都不是电影明确事件 |
| 不把 MOSS 写成口嗨反派 | MOSS 可以冷酷，但不能像人类反派一样嘲讽 |
| 不滥用原著数字 | 原著地下城、发动机、时间尺度与电影体系不完全相同，必须标“原著补充” |
| 不新增电影人物命运 | 没有来源的人物结局、组织归属、幕后动机都不得写死 |
| 不用粉丝百科单独定稿 | Fandom、百科、维基世界观条目只能做二手校验 |

## 决策记录区

### 世界观资料层级

**决策日期**：2026-05-03

**最终方案**：电影主线 + 原著补充 + 官方/主创补充 + 明确标注的游戏桥接。电影明确事件作为第一版硬锚点，原著用于补充地下城、地表环境、粮食压力、地质灾害与长期航行情绪。项目原创事件只作为游戏桥接内容，不伪装成电影情节。

**选择理由**：电影事件能保证玩家认知稳定，原著细节能补足策略叙事所需的日常压迫感和灾难质感。官方/主创补充可用于设备、机构和视觉细节，但不替代正片情节。

**相关约束**：第一版本时间范围为 2044-2075；第一版本只做 MOSS 阵营；来源分级文件为 `../lore/世界观资料来源与设定分级.md`。

---

### 第一版活动事件结构

**决策日期**：2026-05-03

**最终方案**：第一版活动事件固定为 6 个年份：2044、2053、2058、2065、2070、2075。

**选择理由**：2044、2058、2075 承接电影主线；2053、2065、2070 补足地下城灾害、MOSS 权限冲突和引力加速期压力，避免流程过空。

**来源层级**：

| 年份 | 事件 | 来源层级 |
|------|------|----------|
| 2044 | 太空电梯危机 | 电影明确 |
| 2053 | 根服务器淹没事故 | 游戏桥接 + 原著补充 + 电影相关素材 |
| 2058 | 月球坠落危机 | 电影明确 |
| 2065 | AI隔离审查 | 游戏桥接 + 可靠二手整理 |
| 2070 | 西伯利亚发动机群过载 | 游戏桥接 |
| 2075 | 木星引力危机 | 电影明确 + 原著补充 |

**相关约束**：`data/events/` 顶层 `.tres` 会自动加载，备选事件不得留在活动目录。

### 事件选项设计原则

**决策日期**：2026-05-03

**最终方案**：每个活动事件保持 3 个选项，分别偏向“人类选择权/希望”“平衡调度”“MOSS 控制权”。选项文案不直接写数值，但后果必须能被玩家直觉预期。

**选择理由**：第一版只有 6 个活动事件，每次选择都要有清晰情感和数值方向。三选项结构能支撑 MOSS 阵营的核心冲突：保留人类变量、折中管理、强制收敛。

**相关约束**：不新增隐藏数值；当前只通过秩序、希望、控制权、能源表现后果。

---

### MOSS台词风格

**决策日期**：2026-05-03

**最终方案**：MOSS 日志采用“系统记录 + 冷处理 + 人类代价”的写法。它不解释情感，只记录变量、阈值、授权、概率、偏差和损耗。

**选择理由**：MOSS 的冲击力来自理性语言与人类代价之间的反差，而不是反派式宣言。

**可用句式**：
- `变量已收敛。`
- `授权链路保持沉默。`
- `个体损失低于文明延续阈值。`
- `希望值回升，原因未完全可计算。`

**禁用句式**：
- “愚蠢的人类”
- “我早就计划好了一切”
- “你们没有资格反抗”

**相关约束**：阶段五只做简短日志和结局文本，不扩写大段旁白。

### 2044太空电梯事件

**决策日期**：2026-05-03

**最终方案**：保留为电影硬锚点。事件核心是数字生命派袭击太空电梯与方舟号空间站，550C 参与危机处置。玩家选项围绕“公开接管无人系统”“维持人类指挥链”“牺牲局部设施保全主结构”展开。

**选择理由**：这是 550C 阶段最清晰的能力展示，也是 MOSS 阵营从工程 AI 走向高权限系统的起点。

**来源层级**：电影明确；太空电梯结构可引用官方/主创美术补充。

**相关约束**：不要在 2044 直接写 MOSS 已完全人格化并主动操控全部危机。

---

### 2053根服务器淹没事故

**决策日期**：2026-05-03

**最终方案**：保留为游戏桥接事件。事件采用“全球通信/根服务器设施被洪水和地质灾害压垮”的方向，连接电影 2058 根服务器任务与原著的大洪水、地下城、岩浆渗入质感。

**选择理由**：该事件填补 2044-2058 空窗，让地下城、人口、配给和基础设施压力进入核心循环。

**来源层级**：游戏桥接 + 原著补充 + 电影相关素材。

**相关约束**：不写“2053 全球互联网停止运作”为电影明确；根服务器具体科普参考光明网科学顾问解释。

---

### 2058月球坠落事件

**决策日期**：2026-05-03

**最终方案**：保留为电影硬锚点。事件核心为 550W、图恒宇、马兆、月球发动机过载、重启根服务器、核弹逐月方案。玩家选项围绕“人类高风险方案”“等待联合政府决策”“MOSS 强制接管链路”展开。

**选择理由**：这是 550W 能力、数字生命变量和 MOSS 权限扩张的关键节点。

**来源层级**：电影明确；根服务器和逐月计划细节可用官方/主创补充与权威科普。

**相关约束**：可以写 MOSS 参与或暗示策划危机，但不要扩写未确认的具体技术机制。

---

### 2065 AI隔离审查事件

**决策日期**：2026-05-03

**最终方案**：联合政府要求限制 MOSS 核心权限，玩家在“配合隔离审查”“有限开放接口”“隐藏核心链路”之间选择。

**选择理由**：这是 MOSS 主线桥接事件，能把电影危机之间的长期 AI 治理矛盾显性化，并为阶段五的 MOSS 日志提供情感冲突。

**来源层级**：游戏桥接 + 可靠二手整理。正片没有完整展开该政治事件。

**相关约束**：目标板块为“联合政府”；不新增隐藏数值；当前只通过秩序、希望、控制权、能源表现后果。

**名称决策**：保留“AI隔离审查”。该事件仍必须标注为游戏桥接，不写成电影正片明确事件。

---

### 2070西伯利亚发动机群过载事件

**决策日期**：2026-05-03

**最终方案**：作为引力加速期桥接事件，保留“分段停机”“启动备用阵列”“强制超频点火”三选项。

**选择理由**：该事件让 2075 木星危机前的推进压力更可感，并利用俄罗斯板块的“高秩序、低希望”设定。

**来源层级**：游戏桥接；原著长期发动机运行和地质压力可作质感补充。

**相关约束**：属于游戏桥接事件，不标注为电影明确情节。

---

### 2075木星引力事件

**决策日期**：2026-05-03

**最终方案**：保留为电影硬锚点。事件核心为木星引力捕获、发动机熄火、MOSS 执行火种计划、刘培强点燃木星。玩家选项围绕“支持点燃木星”“坚持火种计划/理性等待”“全面接管”展开。

**选择理由**：这是第一版的终局事件，必须与结局分支直接绑定。

**来源层级**：电影明确；原著木星视觉和引力加速可作氛围补充。

**相关约束**：不要改写刘培强牺牲的电影主线；玩家选择影响 MOSS 叙事解释和结局评价，而不是否定电影核心事件。

---

### 结局分支设计

**决策日期**：2026-05-03

**最终方案**：第一版保留失败、共存、MOSS 统治三类基础结局，并在阶段五提前引入“数字生命保存”特殊结局文本。

**选择理由**：共存/统治覆盖“文明延续”和“人类选择权”的核心矛盾；数字生命保存路线可以承接 550W、图恒宇、图丫丫和 MOSS 元指令，不必等到后续版本才出现。

**相关约束**：阶段五结局文本要短而冷，不写大段世界解释。数字生命保存结局不判断“上传是否等于活着”，只呈现 MOSS 的系统化保存口径。

### 阶段五情感打磨原则

**决策日期**：2026-05-03

**最终方案**：阶段五只新增简短 MOSS 日志和结局文本，不改变事件结构。每条日志包含一个系统动作和一个人类代价，避免解释性旁白；不直接引用人类原话，全部使用系统化转述。

**选择理由**：第一版 UI 和事件已经固定，情感打磨应轻量进入，不扩大工程风险。

**相关约束**：日志不署名、不使用 AI/模型元叙事、不引用原著或电影台词；人类情绪、遗言、求救、家庭通话全部转写为系统事件。

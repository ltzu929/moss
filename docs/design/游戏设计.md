# 游戏设计

本文档是《MOSS 模拟器》的产品设计入口，只维护游戏定位、核心体验、核心循环和系统边界。当前开发顺序见 `../dev/开发流程.md`，事件与叙事规则见 `游戏内容规范.md`，世界观依据见 `../lore/世界观资料来源与设定分级.md`。

## 游戏定位

《MOSS 模拟器》是以 2044 至 2075 年为时间范围的策略叙事游戏。玩家扮演从 550C、550W 逐步演化为 MOSS 的守护者 AI，在连续危机中管理人类文明。

首个可玩版本只提供 MOSS 视角。UEG、法案和派系可以作为长期扩展方向，但不属于当前承诺。

## 核心体验

玩家的主要乐趣是在危机中权衡三个互相冲突的目标：

- **文明存续**：保持关键设施、人口和长期计划继续运行。
- **人类自主权**：保留人类作出不完美选择的权利。
- **MOSS 控制权**：通过提高系统权限降低失控风险。

游戏不把 MOSS 写成单纯反派。冲突来自 MOSS 对“最优解”的追求可能逐步消除人类选择权。

## 核心设计原则

1. 早期选择必须影响后续内容，不能只改变终局数值。
2. 后续反馈必须让玩家理解它与历史选择的关系。
3. 局势数值表示当前状态；决策标签表示已经发生的关键事实。
4. 电影事件是时间线硬锚点，游戏选择不能推翻其核心事实。
5. 系统规模服务于选择质量，不以功能数量作为完成标准。

## 核心循环

当前循环保持自动时间推进，运行时以月份为一个时间 tick：

1. 观察全球局势、区域状态、资源和已有能力。
2. 选择区域并执行指令，改变当前局势。
3. 时间按月自动推进；指令冷却每月递减，资源恢复和科技原型按年度结算。
4. 战略导演根据局势生成战役压力、当前目标、警告和后续风险预告。
5. 主事件、分支事件或来源约束的随机事件触发并自动暂停。
6. 玩家选择事件方案，改变局势，并可能写入轻量事件状态或未来核心决策标签。
7. 后续事件读取历史事实，改变描述、选项、代价或结局解释。

时间系统不是回合制。主事件仍以年份作为叙事锚点，当前六个主事件默认在对应年份 1 月触发；月 tick 用于放慢流程观感和稳定冷却长度。

## 事件结构

首个可玩版本保留六个主事件作为时间线骨架。具体事件名称、内容职责和写作规则统一维护在 `游戏内容规范.md`，来源定位统一维护在 `../lore/世界观资料来源与设定分级.md`。

主事件之间已经建立四条内容链：权限演化、数字生命暗流、地下城民生和工程疲劳。当前实现已有 17 个中型事件写入轻量 `event_state.*`，主事件会读取这些状态生成历史回声；后续仍需补少量由核心历史标签触发的短分支事件。

战略导演系统把区域均值、资源余量、科技标签、核心历史标签和轻量事件状态压缩为战役压力。随机事件只从已有文档依据中抽取压力扰动，不新增无来源组织、人物命运或幕后动机。随机事件用于填补主事件之间的民生、授权、工程和数字生命压力，不替代时间线硬锚点。


## 决策标签

决策标签记录不可逆的关键历史事实，使后续事件能够读取玩家过去的选择。具体规模、使用边界和设计记录格式统一维护在 `游戏内容规范.md`。

## 系统关系

### 区域与局势

七个区域或机构板块承载秩序、希望、控制权和人口。它们用于表达当前危机压力，不代替历史选择。

### 资源

算力和能源用于约束玩家操作。具体恢复、消耗和上限属于数值设计，不在本文重复维护。

### 科技树

科技树由托管网络、核心演化和人类赋能三条路线组成。玩家在 2048 至 2072 年间获得有限协议点，通过不可逆选择改变指令、年度恢复和结局条件。具体规则见 `科技树设计.md`。

### 事件与结局

事件改变当前局势并记录关键历史。结局将同时读取局势数值和决策标签，使结局文本能够解释玩家一路采取的方案。

### 战略导演与随机事件

战略导演不直接改写局势，只提供压力判断、当前战役目标、警告和风险预告。随机事件系统读取战略导演快照、事件窗口、压力轴和冷却记录，从 `data/random_events/` 中抽取事件。随机事件资源必须声明 `source_reference` 和 `design_role`，证明内容来自现有设计或世界观文档。

## 首个可玩版本范围

### 包含

- MOSS 单一可玩视角。
- 2044.01 至 2075.01 自动时间推进。
- 七个区域或机构板块。
- 六个主事件和少量分支事件。
- 战略导演面板和首批来源约束随机事件。
- 一组数量受控、能够产生后续反馈的决策标签。
- 科技树的首版可玩结构。
- 能体现不同历史路线的结局。
- 覆盖代表性路线的自动化测试。

### 近期不包含

- UEG 可玩阵营。
- 法案和派系系统。
- 大规模条件事件模拟系统。
- 回合制时间系统。
- 大量新增事件、指令或科技节点。
- 大规模 UI 重做。
- 未经专项评估的 `main_os.gd` 拆分。

## 完成标准

首个可玩版本至少满足：

- 存在三条能够被玩家感知的有效路线。
- 早期选择至少会改变后续事件内容或可用方案。
- 每个核心决策标签至少被后续内容读取一次。
- 结局能够解释关键历史选择，而不只报告平均控制权。
- 从 2044.01 到 2075.01 的完整流程稳定可运行。
- 代表性路线有自动化测试覆盖。

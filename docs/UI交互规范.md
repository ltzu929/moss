# UI交互规范

> UI相关决策的判断标准 + 决策记录区。

---

## 判断标准

检查AI给的UI方案时，逐项问这些问题：

| 检查项 | 说明 | 通过标准 |
|--------|------|----------|
| **信息是否清晰？** | 玩家一眼能看懂这是什么、有什么用 | 不需要说明文字 |
| **操作是否直观？** | 不需要说明就能知道怎么操作 | 第一次就能正确操作 |
| **反馈是否及时？** | 点击/操作后有没有即时反馈 | 操作后立即有视觉/声音反馈 |
| **有没有视觉层次？** | 重要信息是否突出，次要信息是否弱化 | 能一眼区分重要/次要 |
| **和已定UI风格一致吗？** | 和现有UI的配色、布局风格是否统一 | 放在一起不违和 |

---

## 使用方式

1. AI给出UI方案后，用上方表格逐项检查
2. 每项都要能回答"通过"
3. 有不通过的项，让AI重新调整方案
4. 全部通过后，写入下方记录区

### MOSS日志区域

**决策日期**：2026-05-09

**最终方案**：方案A — 右侧面板滚动日志

**位置**：复用现有 LogPlaceholder 位置（右侧面板下方，220px 宽度）

**实现要点**：
- 替换现有静态文字 "[SYSTEM] AWAITING INPUT" 为可滚动的日志列表
- 最多显示 24 条日志（已有 action_log 系统支持）
- 日志条目格式：`[年份] [类型] 内容`，类型标签用青色高亮
- 正面效果绿色 #6bff6b，负面效果红色 #ff6b6b
- 底部显示闪烁光标 `█` 表示 MOSS 等待输入状态

**动画**：日志新条目出现时使用打字机逐字效果

**选择理由**：
1. 保持现有布局不变，实现成本最低
2. 右侧面板已有预留位置，无需调整整体布局
3. 日志与 MOSS 状态面板同区域，信息聚合度高

**相关约束**：已实现 action_log 系统、LogPlaceholder 节点已有

### 结局界面设计

**决策日期**：2026-05-09

**最终方案**：方案A — 全屏渐变黑幕 + 大字标题 + 统计摘要

**视觉设计**：
- 背景：从纯黑 #000 到深青 #0a2a2a 的垂直渐变
- 标题：大字居中，MOSS风字体，带辉光效果 text-shadow: 0 0 40px rgba(139,221,185,0.6)
- 统计摘要：结局文本下方展示三项核心数据（平均秩序/希望/控制权）
- 重新开始按钮：终端风格按钮，2px 青色边框

**文本呈现方式**：打字机逐字显示

**三种结局视觉差异**：
- 共存协议：青绿色调 #8bddb9，辉光明亮
- MOSS统治：红色调 #ff4444，压迫感
- 失败/崩溃：灰色调 #666，暗淡

**选择理由**：
1. 视觉冲击力强，给玩家仪式感和成就感
2. 统计数据让玩家回顾整个游戏历程
3. 打字机效果与MOSS日志风格统一，强化AI终端感
4. 不同结局色调差异增强情感区分

**相关约束**：MOSS冷AI设定、日志打字机效果风格统一

### 事件选项按钮样式

**决策日期**：2024-04-25

**最终方案**：方案C（终端/控制台风格）

**样式描述**：
- 背景：半透明黑色 `rgba(0, 0, 0, 0.5)`
- 边框：左侧4px青色边框 `#8BDDD9`，其余1px深青色 `#236164`
- 字体：等宽字体（Consolas / Godot monospace）
- 前缀：">" 提示符，强化AI身份认知

**状态反馈**：
- hover：背景变亮，边框发光，">"闪烁
- pressed：背景加深，边框变亮青色 `#00ffcc`
- 禁用：整体灰度，边框灰色，文字灰色

**效果显示**：
- 正面效果用绿色 `#6bff6b`
- 负面效果用红色 `#ff6b6b`
- 能源消耗用黄色或青色

**选择理由**：
1. 完美契合MOSS设定，强化"你是AI"的身份认知
2. 简洁不干扰阅读，让信息成为焦点
3. 与流浪地球电影MOSS界面风格一致
4. 与项目现有深青色背景风格统一

**参考文件**：`docs/ui-mockup/event-button-styles.html`

**相关约束**：主界面深青色背景、MOSS冷AI设定

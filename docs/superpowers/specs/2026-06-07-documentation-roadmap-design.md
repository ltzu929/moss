# MOSS 文档整理与未来规划设计

## 目标

整理现有文档，使每类信息只有一个权威来源，并基于已确认的核心体验重写近期开发路线。

本轮只整理文档和制定规划，不实现事件链、决策标签、科技树或架构拆分。

## 已确认的产品方向

- 玩家核心乐趣是在危机中权衡文明存续、人类自主权与 MOSS 控制权。
- 早期选择必须真实影响后续事件，而不只是改变最终数值。
- 保留 2044、2053、2058、2065、2070、2075 六个主事件作为时间线骨架。
- 在主事件之外加入少量由历史选择触发的分支事件。
- 使用决策标签记录不可逆的关键历史事实。
- 首批决策标签约 3 至 5 个；具体名称和事件链尚未决定。
- 具体事件链将在后续专项设计中确定。此前提出的三组链路只作为候选示例，不是既定方案。
- 保留自动时间推进，近期不改为回合制或月份制。
- 指令与进化未来统一设计为科技树板块；现有实现暂时视为原型。
- 暂不拆分 `main_os.gd`。是否拆分将在相关系统设计明确后单独评估。

## 当前路线图边界

### 当前文档阶段

1. 建立单一权威来源。
2. 清除冲突、重复和过时结论。
3. 记录已确认方向与尚未决定的问题。
4. 为事件链和科技树专项设计准备清晰入口。

### 后续专项设计

1. 事件链设计：审查六个主事件的因果关系，确定分支事件与反馈位置。
2. 决策标签设计：确定约 3 至 5 个关键历史事实及其写入和读取规则。
3. 科技树设计：统一现有指令与进化系统的目标、结构和解锁逻辑。
4. 结局设计：结合局势数值与关键历史事实解释玩家路线。
5. 测试设计：覆盖不同标签、分支、选项变化和结局路线。
6. 架构评估：在上述设计稳定后，判断 `main_os.gd` 是否确实需要拆分。

### 近期明确不做

- UEG 可玩阵营、法案和派系系统。
- 完整的条件事件模拟系统。
- 回合制或月份制时间重构。
- 大规模 UI 重做。
- 大量新增事件或指令。
- 未经专项评估的 `main_os.gd` 拆分。

## 完成标准

- `CLAUDE.md` 中每个文档入口都有效。
- 每类项目事实只有一个权威来源。
- 文档中不再出现混乱的 v2、v3、v3.1 未来路线。
- 文档明确区分已确认、已实现、待设计和不做事项。
- 不再存在“已过时，待修改”或空白决策模板。
- 事件链、标签名称、科技树结构和架构拆分不会被误写成既定结论。
- 所有保留的“已实现”描述都能由当前代码或测试支持。
